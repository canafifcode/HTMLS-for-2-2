Designing the Arithmetic Logic Unit

The ALU is the "muscle" of the datapath — a single combinational block that a control unit can command, via a few select lines, to add, subtract, increment, compare, AND, OR, or complement two operands. Today we build one from scratch: half-adder → full-adder → parallel adder → arithmetic circuit → logic circuit → full 4-bit ALU → status register.

Source: Mano, Digital Logic and Computer Design, Ch. 9.3–9.7Level: Combinational logic, already assumes Boolean algebra + K-maps
01

What Is an ALU? Fig. 9-5

An ALU is a combinational circuit that performs both arithmetic and logic operations on binary data, chosen at run time by select inputs — it is not one fixed circuit but a family of circuits multiplexed together.

Fig. 9-5 (redrawn) — A, B: 4-bit operands. s₂s₁s₀: select code. Cin/Cout: carry chain. F: result.

Key idea: s₂ typically picks arithmetic vs. logic mode; s₁s₀ (plus Cin) then pick which operation within that mode. This is exactly the structure we will build, piece by piece.
Exam-style question: Why is Cin listed as a control input, not just a carry?
Because toggling Cin between 0 and 1 lets the same adder hardware realize two related functions — e.g. A+B vs. A+B+1, or (combined with B̄) A+B̄ vs. A+B̄+1 = A−B. This is the trick the whole chapter exploits: reuse one adder for many arithmetic functions instead of building separate circuits.

Building Block 1: The 1-bit Half-Adder

A half-adder adds two single bits x, y and produces a sum S and carry C. It has no provision for an incoming carry — hence "half."

0000
0101

S = x'y + xy' = x ⊕ y
C = xy

Edge case: A half-adder cannot chain — it has no carry-in pin, so it can only ever be the least-significant bit of an adder unless you add extra gates. That's precisely the gap the full-adder fixes.

Building Block 2: The 1-bit Full-Adder

Adds three bits: x, y and an incoming carry z (=Cin), producing sum S and outgoing carry C.

S = x⊕y⊕z   C = xy + xz + yz (majority function — carry out is 1 whenever at least two of the three inputs are 1)

Composition trick: a full-adder = two half-adders + an OR gate. S = HA1.S ⊕ z, and C = HA1.C + HA2.C. This is a classic "build a bigger block from two smaller identical blocks" exam question.
Practice: Derive C = xy + xz + yz directly from the K-map. Show it's the majority function.
Minterms where C=1: 011, 101, 110, 111 (i.e. x'yz, xy'z, xyz', xyz). Grouping pairs in the K-map: {110,111}→xy, {101,111}→xz, {011,111}→yz. Union: C = xy+xz+yz. Each term is "true when two specific inputs are both 1" — exactly majority voting among 3 bits.
04

The Parallel Adder cascaded full-adders

An n-bit parallel adder is n full-adders connected in cascade: the carry-out of stage i feeds the carry-in of stage i+1. This is a ripple-carry adder — simple, but the carry has to physically ripple through all n stages before the final sum is valid (the classic speed/complexity tradeoff, often contrasted with carry-lookahead adders on exams).

Fig. matches slide "Design of Arithmetic Circuit" — note the numbering C1→C5 on the slide corresponds to C1→Cout here.

05

One Adder, Many Operations Fig. 9-9 style

The central insight of ALU design: don't build a separate circuit per operation. Feed the same parallel adder different combinations of (B or B̄) on its second input and different Cin, and you get addition, subtraction, increment, decrement, and pass-through — all from one adder.

Why does A + B̄ + 1 equal A − B? Because 2's complement of B is B̄ + 1. Adding that to A gives A + (2's complement of B) = A − B in modular (wraparound) binary arithmetic. This single identity is worth memorizing cold — it is asked in almost every architecture exam in some form.
Worked problem: A = 0110 (6), B = 0011 (3). Compute F = A + B̄ + 1 and verify it equals A − B.
B̄ = 1100. A + B̄ = 0110 + 1100 = 10010 (5-bit). Add Cin=1: 10011. Drop the overflow carry (5th bit) → F = 0011 = 3.
Check: A − B = 6 − 3 = 3. ✅ Matches. The dropped carry-out (Cout=1) here also tells us "no borrow occurred," i.e. A ≥ B — see the overflow table below.

The True/Complement, One/Zero Circuit Fig. 9-7

Rather than physically inverting B with a separate step, we build a small combinational circuit that, per bit, can output 0, Bᵢ, B'ᵢ, or 1 — selected by two control lines s₁s₀. This is what actually sits between the raw B input and the adder's Y input.

Xᵢ = Aᵢ  (A always passes through unchanged)

Yᵢ = Bᵢs₀ + B'ᵢs₁

One AND gate gated by s₀ passes true B; another AND gate (fed by an inverted B) gated by s₁ passes complemented B; an OR gate merges them. s₁=s₀=1 forces Yᵢ=1 for every bit — that's how "all 1's" is generated for decrement.

Common exam trap: For subtraction, Cout = 0 does not mean an error — it means "a borrow occurred," i.e. A < B, and the true magnitude is recovered by complementing F. Students routinely misread Cout=0 as "invalid result."

Worked Design Example: Single-Select Adder/Subtractor

Problem: Design a circuit with one selection variable s such that s=0 gives F=A+B, and s=1 gives F=A−B via 2's complement of B.

sAᵢBᵢXᵢYᵢ
00000
00101
01010
01111
10001
10100
11011
11110

Solving: Xᵢ = Aᵢ,   Yᵢ = Bᵢ ⊕ s,   Cin = s.

Elegant result: a single row of XOR gates (one per bit, each fed by Bᵢ and the shared control line s) doubles as the "true/complement" selector, and that same s wire is tied directly into Cin. Four XOR gates + one 4-bit adder = a full adder/subtractor. This exact circuit is the heart of virtually every real ALU's add/sub unit.
Exam variant: what happens if you tie s permanently to 0? To 1?
s=0 forever: Yᵢ=Bᵢ, Cin=0 → a plain 4-bit adder (subtractor logic is "dead" hardware). s=1 forever: Yᵢ=B̄ᵢ, Cin=1 → a dedicated subtractor. This shows the same gates can be "hard-wired" into a simpler, fixed-function circuit if the flexibility is never needed — a common area/speed tradeoff discussion point.

Design of the Logic Circuit Fig. 9-11

The logic section is built completely differently from the arithmetic section: instead of an adder, each bit-slice uses a 4-to-1 multiplexer whose four data inputs are the four bitwise functions of Aᵢ, Bᵢ, and whose select lines are s₁s₀.

s₁s₀OutputOperation
00Fᵢ = Aᵢ + BᵢOR
01Fᵢ = Aᵢ ⊕ BᵢXOR
10Fᵢ = AᵢBᵢAND
11Fᵢ = A'ᵢNOT
Notice the logic circuit has no carry chain at all — each bit is fully independent, unlike the arithmetic section. That's a structural difference worth stating explicitly if asked to compare the two halves of an ALU.
11

Combining Logic and Arithmetic Circuits Fig. 9-12

The most direct (if not most efficient) way to merge the two halves: build them as two completely separate circuits, then use a 2-to-1 MUX per bit to pick between them, controlled by the extra mode-select line s₂.

Fig. 9-12 — Simple but wasteful: the arithmetic and logic paths are built as fully separate circuits, and half the hardware is idle at any given moment.

Weakness of this design: it duplicates AND/XOR-type gates that already exist inside the arithmetic circuit's true/complement stage. Section 12 shows how to avoid that duplication.

13

The Status (Flags) Register Fig. 9-14

An ALU alone only computes F — a CPU also needs to react to properties of F (was it zero? negative? did it overflow?). Four flag bits, typically labeled C S Z V, capture this after every ALU operation.

  • C (Carry): set to the ALU's Cout directly.
  • S (Sign): set to the most-significant (sign) bit of F. 1 = result is negative in signed 2's-complement.
  • Z (Zero): set when F is all zero bits — implemented as a big NOR across every output bit.
  • V (Overflow): set when C(n-1) ⊕ Cn = 1, i.e. the carry into the sign bit differs from the carry out of the sign bit. For an 8-bit ALU this fires exactly when the true signed result falls outside [−128, 127].
Classic exam trap: C and V answer different questions. C=1 signals unsigned overflow (result exceeded 2ⁿ−1 treating operands as unsigned). V=1 signals signed overflow. A calculation can set one without the other — e.g. adding two large positive signed numbers can set V=1 while C=0.
Worked problem: A = 01111111 (127), B = 00000001 (1), 8-bit signed add. Find C, S, Z, V.
127 + 1 = 128 unsigned = 10000000 binary. F = 10000000.
C = 0 (no carry out of bit 7, since 128 < 256).
S = 1 (MSB of F is 1).
Z = 0 (F ≠ 0).
V: carry into bit7 (C7) = 1 (from 0111111+0000001 in bits 0-6... let's trust the standard result): here C7=1, C8(Cout)=0 → V = C7⊕C8 = 1. V=1: correctly flags that 127+1=128 overflowed the signed 8-bit range (max +127). Even though C=0, this is a signed overflow.

One-Page Cheat Sheet

Must-know identities

  • 2's complement of B = B̄ + 1 → subtraction is "add the complement": A − B = A + B̄ + 1
  • Half-adder: S = x⊕y, C = xy — no carry-in support.
  • Full-adder: S = x⊕y⊕z, C = xy+xz+yz (majority function).
  • True/complement/0/1 selector: Yᵢ = Bᵢs₀ + B'ᵢs₁ — lets one adder input become 0, B, B̄, or all-1's.
  • Ripple-carry adder = n full-adders, Cout of stage i → Cin of stage i+1.
  • Logic stage ≠ arithmetic stage: logic uses an independent MUX per bit, no carry chain.
  • Unified ALU: force Cin=0 in logic mode (via Zᵢ = s₂′Cᵢ) so the two modes can share the same adder gates.
  • Flags: C=Cout · S=sign bit of F · Z=NOR of all F bits · V = C(n-1) ⊕ Cn.
