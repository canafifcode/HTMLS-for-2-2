Three exams, one toolkit

Reading all three specs together

Strip away the surface differences and A1/A2, B1/B2, and C1/C2 are the same exam wearing three costumes. Each one hands you a variant of the Signal/LTI_System classes you built in Offline 1, and asks you to compute an output without ever calling a built-in convolution function — by routing the computation through a different mathematical identity each time.

All three share the same DNA: a Signal object that stores samples over a symmetric window [−INF, INF], and an LTI_System that turns an input into an output by re-using the impulse-decomposition machinery you already wrote for Offline 1. None of them let you call numpy.convolve — the entire point is that you already own a correct convolution engine, and each online just asks you to drive it through a different route.

The one habit that pays off across all three

Before writing a line of code, work out the answer by hand on a tiny example — three or four taps, nothing more. Every identity in this guide (first difference, network composition, superposition) reduces to ordinary finite convolution once you strip the story away, and a hand-checked example is the fastest way to catch a sign error before it costs you marks. This guide computes every worked example both ways so you can see the pattern.

Signal — a windowed array with a symmetric index

A Signal stores samples for n ∈ [−INF, INF] in a plain array, with n = 0 mapped to the middle. Everything else — shifting, adding, scaling — is array arithmetic once you get the index offset right.

signal.pySignal class
class Signal:
    def __init__(self, INF):
        self.INF = INF
        self.values = np.zeros(2 * INF + 1)

    def _idx(self, t):
        return t + self.INF

    def set_value_at_time(self, t, value):
        if -self.INF <= t <= self.INF:
            self.values[self._idx(t)] = value

    def get_value_at_time(self, t):
        if -self.INF <= t <= self.INF:
            return self.values[self._idx(t)]
        return 0.0

    def shift(self, k):
        # returns a NEW signal y such that y[n] = self[n - k]
        shifted = Signal(self.INF)
        for n in range(-self.INF, self.INF + 1):
            shifted.set_value_at_time(n, self.get_value_at_time(n - k))
        return shifted

    def add(self, other):
        result = Signal(self.INF)
        result.values = self.values + other.values
        return result

    def multiply(self, scalar):
        result = Signal(self.INF)
        result.values = self.values * scalar
        return result

    def plot(self, title="Discrete Signal"):
        n = np.arange(-self.INF, self.INF + 1)
        plt.figure(figsize=(8, 3))
        plt.stem(n, self.values)
        plt.title(title); plt.xlabel("n"); plt.grid(True)
        plt.show()
Exam alert · shift(k) is a delay, not an advance

shift(k) must return y[n] = x[n−k] — the signal delayed by k. It is extremely easy to write get_value_at_time(n+k) by reflex and silently build an advance instead. Test it once: shift a signal with a single sample at n=0 by k=2 and confirm the sample now sits at n=2, not n=−2.

LTI_System — convolution via the impulse decomposition

The method name linear_combination_of_impulses is not decoration — it is the actual proof that convolution works, turned into code. Any discrete signal can be written exactly as a sum of scaled, shifted impulses:

x[n] = Σk x[k] · δ[n−k]

Feed δ[n−k] into an LTI system and by definition you get h[n−k] back — a shifted copy of the impulse response. By linearity, the response to the whole sum is the sum of the responses:

y[n] = Σk x[k] · h[n−k] = (x ∗ h)[n]
lti_system.pyLTI_System class
class LTI_System:
    def __init__(self, impulse_response: Signal):
        self.h = impulse_response
        self.INF = impulse_response.INF

    def linear_combination_of_impulses(self, input_signal: Signal):
        # every nonzero sample x[k] becomes a (shift, weight) pair
        impulses = []
        for k in range(-self.INF, self.INF + 1):
            ck = input_signal.get_value_at_time(k)
            if ck != 0:
                impulses.append((k, ck))
        return impulses

    def output(self, input_signal: Signal) -> Signal:
        y = Signal(self.INF)
        for k, ck in self.linear_combination_of_impulses(input_signal):
            term = self.h.shift(k).multiply(ck)   # ck * h[n-k]
            y = y.add(term)
        return y
Why every spec insists "reuse your Offline 1 code"

output() never changes across A/B/C. What changes is what you construct and hand to it — a step response instead of an impulse response (Track A), a composed network response (Track B), or a batch of scaled inputs summed after the fact (Track C). The graders are really testing whether you understand that convolution is one operation wearing different inputs, not three different algorithms.

Track A — step response and the first difference

A1 / A2 spec · files: step_response.txt, input_signal.txt

You're not given h[n] directly this time — only the step response s[n], the system's reply to a permanent switch-on rather than a single poke. The whole task is built on one identity that turns differencing into deconvolution.

Where the identity comes from

The unit step is the running sum of the unit impulse: u[n] = Σk≤n δ[k]. So the step response is what you get by feeding an LTI system the accumulated impulse — which, by linearity, is the accumulated impulse response:

s[n] = (u ∗ h)[n] = Σk=−∞n h[k]

Differencing undoes summing. Subtract consecutive step-response samples and the running sum collapses back to a single term:

s[n] − s[n−1] = Σk≤nh[k] − Σk≤n−1h[k] = h[n]

For the output identity, start from ordinary convolution and use the fact that h = s − sshift 1, together with the associativity of convolution:

y = x ∗ h = x ∗ (s − sshift1) = (x − xshift1) ∗ s = Δx ∗ s

The step response only has to be convolved with the changes in the input, not the input itself — every stretch where x is constant contributes nothing to Δx.

Brainstorm · a one-line sanity check before you code anything

Since h = s − sshift1, the samples of h must always sum to the step response's final settled value: Σh[k] = s[∞] (a telescoping sum). If your recovered h doesn't sum to the plateau you can see in the s[n] plot, something is off before you even get to convolution.

Edge case · the mismatch you'll actually see past n = 30, and why it's not a bug

Push the comparison past n = 30 (if your INF is large enough to reach there) and ys and yh visibly diverge — by as much as 1.2 at some samples. This is a genuine property of the dataset, not an implementation bug. s[n] is a step response: physically it keeps sitting at its plateau (0.6) forever. But the file only tabulates it up to n = 30, so any array-based Signal silently treats s[n] as 0 beyond that point — a value it never actually takes. Δx∗s needs s at arbitrarily large arguments (because Δx has taps as late as n=26), so it inherits this truncation error. h, by contrast, is genuinely FIR — it is exactly zero past n=8 in reality, not just in the file — so x∗h is unaffected. If your own np.allclose check fails, look at which tail samples disagree before assuming your convolution code is wrong — compare only over n ≤ 30, or extend s with its plateau value out to INF, and the mismatch disappears.

def first_difference(sig: Signal) -> Signal:
    # sig[n] - sig[n-1], built only from shift / multiply / add
    return sig.add(sig.shift(1).multiply(-1))

def impulse_from_step_response(step_response: Signal) -> Signal:
    return first_difference(step_response)

def output_using_step_response(x: Signal, step_response: Signal) -> Signal:
    dx = first_difference(x)
    sys_s = LTI_System(step_response)     # reuses Offline 1 machinery
    return sys_s.output(dx)               # (Δx * s)


if __name__ == "__main__":
    INF = 50
    s = read_signal_from_file("step_response.txt", INF)
    x = read_signal_from_file("input_signal.txt", INF)

    h = impulse_from_step_response(s)
    s.plot("Step Response s[n]")
    h.plot("Recovered Impulse Response h[n] = s[n] - s[n-1]")

    y_s = output_using_step_response(x, s)
    x.plot("Input x[n]")
    dx.plot("First Difference Δx[n]")

Track B — combining a network of LTI blocks

B1 / B2 spec · three impulse responses, one diagram

The spec's figure shows x[n] passing through h1 in series, then splitting into two parallel branches — one a straight passthrough, one filtered by h2 — which are summed and finally passed through h3 in series. Reading the diagram correctly is most of the task.

x[n] → h1[n] → split into (passthrough) ∥ (h2[n]) → sum → h3[n] → y[n]

Reducing the network to one impulse response

Two rules do all the work, and both fall straight out of the algebra of convolution:

ConnectionRuleWhy
Series (cascade)htotal = h1 ∗ h2Associativity: (x∗h1)∗h2 = x∗(h1∗h2)
Parallel, summedhtotal = h1 + h2Distributivity: x∗h1 + x∗h2 = x∗(h1+h2)

The "passthrough" branch is just a cascade with the identity system, whose impulse response is δ[n] (it outputs whatever it's fed, unchanged). So the parallel pair (passthrough ∥ h2) reduces to a single block with impulse response δ + h2, and the whole network becomes three systems in series:

hcombined = h1 ∗ (δ + h2) ∗ h3
Brainstorm · order doesn't matter, but bookkeeping does

Convolution is commutative and associative, so you can convolve h1, (δ+h2), and h3 in any order and land on the same hcombined. What you can't do is skip the δ: forgetting the passthrough branch and computing h1∗h2∗h3 silently deletes an entire signal path from the diagram — a very easy way to lose most of the marks on this task while producing a plausible-looking, wrong plot.

Worked solution using the spec's own example signals

The template initialises x = {1 at n=0, −1 at n=2}, h1 = {1 at n=0} (the identity — h1 does nothing), h2 = {0.5 at n=1}, h3 = {1 at n=0, 1 at n=1} (a two-tap averager-like sum).

Block-by-block route

v = x∗h1 = x (h1 is δ) = {1@0, −1@2}

v∗h2 = {0.5@1, −0.5@3}

w = v + v∗h2 = {1@0, 0.5@1, −1@2, −0.5@3}

y = w∗h3 = {1@0, 1.5@1, −0.5@2, −1.5@3, −0.5@4}

Combined-h route

(δ+h2) = {1@0, 0.5@1}

∗h3 ⟹ h1∗(δ+h2)∗h3 = hcombined = {1@0, 1.5@1, 0.5@2}

y = x∗hcombined = {1@0, 1.5@1, −0.5@2, −1.5@3, −0.5@4}

Both routes agree, to the sample

Both columns land on exactly the same five-sample output. As a final check: Σhcombined = 1+1.5+0.5 = 3, and (Σh1)(Σδ+h2)(Σh3) = 1 × 1.5 × 2 = 3 ✓. Σy = 1+1.5−0.5−1.5−0.5 = 0, matching (Σx)(Σhcombined) = (1−1)×3 = 0 ✓.

Complete solution

sys1 = LTI_System(h1)
sys2 = LTI_System(h2)
sys3 = LTI_System(h3)

# ---- Block-by-block route ----
v = sys1.output(x)                 # x * h1
top    = v                         # passthrough branch
bottom = sys2.output(v)            # v * h2
w = top.add(bottom)                # sum at the junction
y_final_1 = sys3.output(w)         # w * h3

# ---- Combined impulse-response route ----
delta = Signal(INF)
delta.set_value_at_time(0, 1.0)

inner = delta.add(h2)              # δ + h2  (passthrough ∥ h2, as one block)
h1_then_inner = LTI_System(inner).output(h1)   # h1 * (δ + h2)
h_combined     = LTI_System(h3).output(h1_then_inner)  # ... * h3

sys_combined = LTI_System(h_combined)
y_final_2 = sys_combined.output(x)

y_final_1.plot("Output via block-by-block system")
y_final_2.plot("Output via combined impulse response")

print("Outputs are equal:",
      np.allclose(y_final_1.values, y_final_2.values))
Exam alert · read the diagram before you touch the keyboard

B-type diagrams vary — the passthrough branch might sit on h2's side instead of being bare, or there might be no passthrough at all (pure parallel). Trace the arrows from x[n] to y[n] on paper first, write down which blocks are in series (multiply their transfer effect via convolution) and which are alternatives feeding the same summing junction (add), and only then translate to code. Track C — superposition of multiple signals

C1 / C2 spec · SuperSignal and output_super

This spec tests linearity in its most literal form: build a signal as a weighted sum of other signals, and compute the LTI output without ever materialising the sum as a single array first — by convolving each component separately and combining afterward.

The principle

If x[n] = Σi cixi[n], linearity of convolution gives immediately:

y[n] = (x ∗ h)[n] = Σi ci (xi ∗ h)[n]

The template already gives you SuperSignal as a list of (coefficient, Signal) pairs. Your job is the LTI_System method that walks that list, convolves each component against h independently, scales, and sums.

lti_system.pyadd this method to LTI_System
def output_super(self, supersignal: "SuperSignal") -> Signal:
    y = Signal(self.INF)
    for coeff, sig in supersignal.components:
        y = y.add(self.output(sig).multiply(coeff))
    return y
Brainstorm · why bother, if you could just build x[n] directly?

For this particular assignment you could add up the components into one Signal first and call output once — you'd get the same answer, because convolution is linear either way. The reason the spec insists on component-wise processing is that it's the pattern used everywhere real signal systems are built: filter banks, modulated carriers, multi-source superposition in physics. Practising it here, on an example small enough to check by hand, is the whole point.

Worked solution using the spec's own example signals

The template gives x1 = {1 at n=0}, x2 = {1 at n=2}, and h = {1 at n=0, 0.5 at n=1}, with the SuperSignal defined as x[n] = 2x1[n] − x2[n].

Component by component

x1∗h = {1@0, 0.5@1}

x2∗h = {1@2, 0.5@3}

2·(x1∗h) = {2@0, 1@1}

−1·(x2∗h) = {−1@2, −0.5@3}

Summed result

y = 2(x1∗h) − (x2∗h) =
{2@0, 1@1, −1@2, −0.5@3}

Cross-check: build x = 2δ − δshift2 = {2@0, −1@2} directly and convolve with h in one shot — same four samples, exactly.

Exam alert · negative coefficients are still just coefficients

multiply(scalar) must work for negative and fractional scalars exactly as it does for positive ones — there is no special case to add. If your Signal.multiply was only ever tested with positive integers in Offline 1, this is the moment a hidden sign bug in it will surface. Test x1.multiply(-1) against a hand-checked example before trusting output_super.

Practice bank — Track A (step response)

Practice A · step response and first difference

A discrete LTI system has step response s[n] = 0 for n < 0, s[0] = 1, s[1] = 1, s[2] = 2, and s[n] = 2 for all n ≥ 2. The input is x[0] = 1, x[1] = −1, zero elsewhere.

Find the recovered impulse response h[n], the first difference Δx[n], and the output y[n] — computed both as Δx∗s and as x∗h, and confirm they agree.

Step 1 · recover h[n]

h[n] = s[n] − s[n−1]: h[0] = 1−0 = 1, h[1] = 1−1 = 0, h[2] = 2−1 = 1, h[n] = 0 for n ≥ 3 (s stays flat at 2). So h = {1@0, 1@2}. Check: Σh = 2 = s[∞] ✓.

Step 2 · first difference of x

Δx[0] = 1−0 = 1, Δx[1] = −1−1 = −2, Δx[2] = 0−(−1) = 1. So Δx = {1@0, −2@1, 1@2}. (Note it sums to zero, as it must whenever x starts and ends at 0.)

Step 3 · y via x ∗ h (the reliable route — h is FIR)

y[n] = x[n] + x[n−2] (since h has unit taps at 0 and 2): y = {1@0, −1@1, 1@2, −1@3}.

Step 4 · y via Δx ∗ s, and the edge case it reveals

Convolving the three-tap Δx against s (treating it as tabulated only up to n=5, i.e. zero beyond) gives the same four core samples {1@0, −1@1, 1@2, −1@3} — but also two small extra "ghost" samples at n=6 and n=7 (values −2 and +2), which appear only because the array representation of s falsely drops back to 0 after n=5 instead of staying at its true plateau of 2 forever. Exactly the same phenomenon as the real A1/A2 dataset, just with two ghost samples instead of many — because Δx sums to zero here too, these ghosts always cancel out eventually and don't reflect a real system behaviour.

Practice bank — Track B (network combination)

A second topology: pure parallel, then series

x[n] → split → h1[n] ∥ h2[n] → sum → h3[n] → y[n]

Practice B · pure-parallel-then-series network

With the topology above, let x = {1@0, 1@2}, h1 = {1@0} (identity), h2 = {1@1} (unit delay), h3 = {1@0, −1@1}.

Find hcombined and y[n], both by the block-by-block route and by combining first.

Step 1 · combine the parallel pair

h1 + h2 = {1@0, 1@1} — a two-tap running-sum filter.

Step 2 · put it in series with h3

hcombined = (h1+h2) ∗ h3 = {1@0,1@1} ∗ {1@0,−1@1}. Multiply out: n=0: 1·1=1; n=1: 1·(−1)+1·1=0; n=2: 1·(−1)=−1. So hcombined = {1@0, −1@2} — the middle tap cancels exactly, which is worth noticing: h3 is a first-difference-style filter, and it differentiates away the constant part of a running sum.

Step 3 · output

y = x ∗ hcombined = {1@0,1@2} ∗ {1@0,−1@2}: n=0: 1; n=2: 1·(−1)+1·1=0; n=4: 1·(−1)=−1. So y = {1@0, −1@4} (the n=2 term cancels).

Cross-check · block-by-block

x∗h1 = {1@0,1@2}; x∗h2 = {1@1,1@3}; sum w = {1@0,1@1,1@2,1@3}; w∗h3 = {1@0, (1−1)@1, (1−1)@2, (1−1)@3, −1@4} = {1@0, −1@4} — identical. ✓ Try both topologies in the Interactive Lab above to watch this happen live.

Practice bank — Track C (superposition)

Three components this time, not two
Practice C · three-component superposition

An LTI system has impulse response h = {1@0, 1@1, 0.5@2}. Three unit impulses are defined: x1 = {1@0}, x2 = {1@1}, x3 = {1@3}, combined as x[n] = 3x1[n] − 2x2[n] + x3[n].

Find y[n] using output_super (component by component), and verify by building x[n] directly and convolving once.

Step 1 · convolve each component with h separately

x1∗h = {1@0, 1@1, 0.5@2} (h itself, unshifted, since x1=δ)
x2∗h = {1@1, 1@2, 0.5@3} (h shifted right by 1)
x3∗h = {1@3, 1@4, 0.5@5} (h shifted right by 3)

Step 2 · scale each by its coefficient and sum

3·(x1∗h) = {3@0, 3@1, 1.5@2}
−2·(x2∗h) = {−2@1, −2@2, −1@3}
