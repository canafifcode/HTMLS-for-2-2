Systems: signals go in, signals come out

The single mental shift this lecture demands of you.

An ordinary function eats one number and returns one number. A system eats an entire signal and returns an entire signal. That is a genuinely bigger object: the input is a whole function of time, not a sample.

x(t)  ⟶  S  ⟶  y(t)     x[n]  ⟶  S  ⟶  y[n]
Why the distinction matters

Because a system may look at times other than "now". A moving average y[n] = (x[n] + x[n−1])/2 needs the past. An ideal differentiator needs neighbouring instants. If you keep thinking "one number in, one number out", every one of these looks impossible.

The mathematical notation you'll see

We write y(t) = S{x(t)} or x(t) → y(t). The arrow is not an equality — it means "this input produces that output through the given system." Writing y(t) = S{x(t)} and then substituting t → t−t₀ carelessly is the single most common source of errors in time-invariance proofs, and we'll handle it very carefully in section 3.

Linearity

Scaling the input scales the output; adding inputs adds outputs.

Linearity is two promises bundled together.

Definition

Homogeneity (scaling): if x(t) → y(t), then a·x(t) → a·y(t) for every constant a.

Additivity (superposition): if x₁ → y₁ and x₂ → y₂, then x₁ + x₂ → y₁ + y₂.

Combined into one statement — the form you should actually use in exams:

a·x₁(t) + b·x₂(t)  ⟶  a·y₁(t) + b·y₂(t)

The zero-in, zero-out corollary

Put a = 0 in homogeneity: a zero input must give a zero output. This gives you a free instant disqualifier. If a system produces something out of nothing, it is not linear, and you need not write another line.

Edge case that traps everyone

y(t) = 2x(t) + 3 is not linear, despite looking like the equation of a straight line. Zero in gives 3 out. Systems of this shape are called incrementally linear: the deviation from a fixed offset behaves linearly. Examiners love this one precisely because "linear" in the everyday sense misleads you.

Careful though — zero-in-zero-out is necessary, not sufficient. y[n] = x[n]² passes it and is still nonlinear (check: (x₁+x₂)² ≠ x₁² + x₂²).

How to actually test linearity — the two-column method

  1. Let x₁ → y₁ and x₂ → y₂, writing both outputs explicitly from the system rule.
  2. Form x₃ = a x₁ + b x₂ and push it through the rule to get y₃.
  3. Separately form a y₁ + b y₂.
  4. If steps 2 and 3 agree for all a, b, x₁, x₂ → linear. Otherwise produce one concrete counterexample.
Worked: is the accumulator linear?

y[n] = Σk=−∞n x[k]. Then

Σk≤n (a x₁[k] + b x₂[k]) = a Σk≤n x₁[k] + b Σk≤n x₂[k] = a y₁[n] + b y₂[n] ✓

Linear, because summation itself is a linear operation. The same argument makes integration, differentiation and delay all linear.

Brainstorm

Is y(t) = t·x(t) linear? Multiply-by-t looks time-dependent and suspicious — but linearity says nothing about t-dependence. Check: t(a x₁ + b x₂) = a·t x₁ + b·t x₂. Yes, linear. (It fails time-invariance instead — section 3.) Keeping these two properties in separate mental boxes is half the battle.

Time-invariance

Delay the input, and the only thing that changes is that the output is equally delayed.

A time-invariant system has no clock of its own. It does not care whether you run the experiment now or tomorrow — the shape of the response is identical, just moved along the time axis.

If   x(t) ⟶ y(t),   then   x(t − t₀) ⟶ y(t − t₀)   for every t₀

The slide's Mr. Bean panels make exactly this point: shift the film reel, and the processed film is the same film, shifted.

The airtight test (write it this way every time)

Path A — delay the output. Compute y(t) from the rule, then replace every free t by t − t₀. Call it y(t − t₀).

Path B — delay the input. Define x₁(t) = x(t − t₀), feed x₁ into the rule, and get y₁(t).

Verdict. Time-invariant ⟺ y₁(t) = y(t − t₀) identically.

Worked example 1 — y(t) = t·x(t)

Path A: y(t − t₀) = (t − t₀)·x(t − t₀). Path B: y₁(t) = t·x₁(t) = t·x(t − t₀). These differ (the multiplier is t, not t − t₀). Not time-invariant. The system has an explicit clock built in.

Worked example 2 — y[n] = x[2n]

Path A: y[n − n₀] = x[2(n − n₀)] = x[2n − 2n₀]. Path B: y₁[n] = x₁[2n] = x[2n − n₀]. A delay of n₀ at the input becomes a delay of n₀, but the output-delayed version wants 2n₀. Not time-invariant.

Edge cases worth memorising
  • y(t) = x(−t) (time reversal): linear ✓, time-invariant ✗.
  • y[n] = n·x[n]: linear ✓, TI ✗.
  • y[n] = x[n]²: linear ✗, TI ✓.
  • y(t) = x(t) + 3: linear ✗, TI ✓.
  • y[n] = x[n−3]: linear ✓, TI ✓ — an LTI system.

The two properties are logically independent. Any of the four combinations can occur. Never infer one from the other.

Putting them together: LTI

Two modest-looking properties that will hand us the output for every input.

A system that is both Linear and Time-Invariant is called LTI. The payoff, which the rest of this lecture builds toward:

For an LTI system, one single measurement — the response to one impulse — determines the response to every input signal that will ever be applied.

That is an extraordinary claim. There are infinitely many possible inputs; we are saying one number-sequence characterises the whole system. Sections 6–9 prove it.

Exam tactic

To disprove a property, one concrete counterexample is a complete answer and is far faster than symbol-pushing. To prove it, you must argue for arbitrary a, b, x₁, x₂, t₀. Marks are routinely lost by "proving" linearity with one specific pair of signals.

A detour: where convolution comes from

Before we need it, let's meet it in a place you already know — multiplying polynomials.

Given two sequences you can add them, subtract them, multiply them pointwise. Convolution is a fourth, stranger kind of mixing — and it appears the moment you multiply two polynomials.

A(z) = 1 + 3z + 2z² + 5z³ + 4z⁴  →  a = {1, 3, 2, 5, 4}

B(z) = 2 − z + 4z² + z³ + 3z⁴  →  b = {2, −1, 4, 1, 3}

Question: what is the coefficient of z⁴ in A(z)·B(z)?

You collect every product whose powers add to 4 — the criss-crossed pairings a₀b₄, a₁b₃, a₂b₂, a₃b₁, a₄b₀:

c[4] = 1·3 + 3·1 + 2·4 + 5·(−1) + 4·2 = 3 + 3 + 8 − 5 + 8 = 17

In general the coefficient of zⁿ is

c[n] = Σk a[k]·b[n − k]

The key reading of b[n − k]

Look at that index. As a function of k, the expression n − k does two things: the minus sign reflects the sequence, and the n shifts the reflected copy to the right by n. Reflection is what converts awkward criss-crossed pairings into tidy vertical pairings. That is the whole trick.

Index expressionEffect on b
b[k]original
b[−k]reflected about k = 0
b[n − k]reflected, then shifted right by n

Check it against the slides: at n = 0 only one pair overlaps, giving c[0] = 1·2 = 2. At n = 2, three pairs overlap: 1·4 + 3·(−1) + 2·2 = 5. At n = 4 all five line up and reproduce 17. Same number, obtained by sliding instead of criss-crossing.

The recipe (worth writing on the inside of your eyelids)

Keep the first signal as it is. Reflect the second. Slide it rightward. At each position, multiply the overlapping values and add them.

c[n] = (a ∗ b)[n] = Σk = −∞∞ a[k]·b[n − k]
Why this identity is more than a curiosity

Polynomial multiplication = convolution of coefficient sequences. This is why long multiplication of ordinary numbers is also a convolution (with carries), why the z-transform will later turn convolution into plain multiplication, and why fast polynomial multiplication (FFT) is the same algorithm as fast convolution. You are meeting a very deep operation in a very friendly costume.

The answer, and three checks you should always run

y[n] = {1, 3, 2, 2, 4, 1, 2},   n = 0 … 6
Three-second sanity checks
  1. Length. A length-N sequence convolved with a length-M sequence has length N + M − 1. Here 4 + 4 − 1 = 7 ✓
  2. Support / start index. If x starts at n₁ and h at n₂, then y starts at n₁ + n₂ and ends at (end of x)+(end of h). Here 0+0 = 0 to 3+3 = 6 ✓
  3. Sum test. Σy = (Σx)(Σh). Here Σx = 5, Σh = 3, and Σy = 1+3+2+2+4+1+2 = 15 = 5×3 ✓ (This follows from setting z = 1 in the polynomial picture.)

These three catch the overwhelming majority of arithmetic slips, and they cost you almost nothing.

Does the order matter?

No. a ∗ b = b ∗ a. The polynomial view makes this obvious: A(z)B(z) = B(z)A(z), and the coefficients cannot know which polynomial you wrote first. Formally, substitute m = n − k in the sum and it turns into the other one.

PropertyStatementMeaning for systems
Commutativex ∗ h = h ∗ xYou may reflect whichever sequence is easier — reflect the shorter one.
Associative(x∗h₁)∗h₂ = x∗(h₁∗h₂)Two LTI systems in cascade = one system with h₁∗h₂.
Distributivex∗(h₁+h₂) = x∗h₁ + x∗h₂Two LTI systems in parallel = one system with h₁+h₂.
Identityx ∗ δ = xδ[n] is the do-nothing system.
Shiftx ∗ δ[n−n₀] = x[n−n₀]Convolving with a shifted impulse just shifts.
Practical tip

Because convolution is commutative, in a hand computation always reflect and slide the shorter sequence — fewer terms per column, fewer chances to slip. Cascade order is also free: for h₁ ∗ h₂ ∗ h₃ you may pick whichever grouping is least painful.

Why we needed convolution at all

The strategy: solve the simplest input, decompose everything else into copies of it.

The ambitious problem is: given an LTI system and any input x(t), find y(t) — systematically, without re-deriving from scratch each time.

A number-theory rehearsal

The slides warm up with: how many positive factors does 72 have? Testing 1…72 works but is dumb. Instead:

72 = 2³ · 3²  ⟹  (3+1)(2+1) = 4 × 3 = 12 factors

The powers of 2 available are 2⁰,2¹,2²,2³ — four choices; the powers of 3 are 3⁰,3¹,3² — three choices. Every factor is one choice of each.

The philosophy, in three lines
  1. Solve the problem for the simplest possible pieces.
  2. Break any complicated object into those pieces.
  3. Combine the small answers.

Step 3 is exactly where linearity earns its keep: it is the licence to combine. Step 2 needs a decomposition; step 1 needs a "simplest input". Both are about to be supplied by the impulse.

Brainstorm

The same three-line philosophy is coming back twice more in this course. In Lecture 5 (Fourier series) the "simple pieces" are complex exponentials instead of impulses, and the combination is a sum of harmonics. Later, the Laplace/z-transforms swap the basis again. Different basis, identical strategy. If you internalise it here, those lectures become re-runs.

The impulse and the impulse response

Poke the system once. Watch what it does. That's the whole system.

The discrete-time unit impulse is zero everywhere except a single instant:

δ[n] = 1 if n = 0,   0 otherwise

Feed it into the system. Whatever comes out is called the impulse response, written h[n]:

δ[n]  ⟶  S  ⟶  h[n]

The slides use a lovely image: poking a sleeping cat. One sharp, instantaneous input; a long, elaborate, system-specific response. That response is the system's signature.

Example A — the toy echo room

Shout one short "hello" in a hard-walled room; you hear it repeated, and in the idealised toy version each echo is equally loud and they never stop:

h[n] = u[n]

Note what kind of system this is: an accumulator. Convolving with u[n] is the same as taking a running sum — which we'll see in a moment.

Example B — fading echoes

Real rooms absorb energy. Let a fraction α of the sound survive each reflection:

h[n] = αⁿ·u[n],   0 < α < 1   ⟹   1, α, α², α³, …
Echo decay: what does α actually control? α is the survival fraction per reflection
0.70
Edge cases in α — a favourite exam probe
  • α = 0: h[n] = δ[n]. Anechoic — the do-nothing system.
  • 0 < α < 1: decaying echoes. Σ|h[n]| = 1/(1−α), finite → stable.
  • α = 1: h[n] = u[n]. Echoes never die. Σ|h[n]| = ∞ → not BIBO stable (feed it a constant input and the output grows without bound).
  • α > 1: echoes grow louder — an unstable, howling room.
  • α < 0: alternating signs. Each reflection flips polarity.

So the innocent toy echo system with h = u[n] sits exactly on the stability boundary. Lecture 4 makes this precise.

Example C — pure delay

Suppose y[n] = x[n − 3]. What is its impulse response? Put x = δ: out comes δ[n − 3].

h[n] = δ[n − 3]     (continuous-time: h(t) = δ(t − 3))

The bridge: from one impulse to any input

Where convolution stops being a curiosity and becomes the input–output law of LTI systems.

Step 1 — decompose the input

Any discrete-time signal is a stack of scaled, shifted impulses. The sample value x[k] becomes the height of an impulse sitting at n = k:

x[n] = Σk = −∞∞ x[k]·δ[n − k]

This identity is the sifting property read backwards, and it is exact, not an approximation. Verify it at one point: on the right-hand side, every term with k ≠ n has δ[n−k] = 0, so only the k = n term survives and gives x[n]. ✓

Step 2 — LTI tells us each piece's output

Time-invariance:   δ[n] → h[n]  ⟹  δ[n − k] → h[n − k]

Linearity (scaling):   x[k]·δ[n − k] → x[k]·h[n − k]

Linearity (adding):   the sum of the pieces produces the sum of the responses.

Step 3 — add everything up

y[n] = Σk = −∞∞ x[k]·h[n − k] = (x ∗ h)[n]

And there it is — the very same sliding multiply-and-add we met in polynomial multiplication, now derived as the universal input–output relation for every LTI system in existence.

The lecture's concrete demonstration

Send a four-sample input into the toy echo room (h = u[n]):

x[n] = δ[n] + 2δ[n−1] − δ[n−2] + δ[n−3]

Each input sample launches its own scaled, shifted copy of the impulse response — four staircases — and the output is their sum:

y[n] = u[n] + 2u[n−1] − u[n−2] + u[n−3]
Superposition, one piece at a time watch the four staircases accumulate
0

The output settles at 3 for all n ≥ 3 — which is just 1 + 2 − 1 + 1, the total of the input. Convolving with u[n] gives the running sum, exactly as promised.

The bridge, in one frame
  1. Find the response to the simplest input:  δ[n] → h[n].
  2. Break any input into shifted impulses:  x[n] = Σ x[k]δ[n−k].
  3. Shift, scale, add the impulse responses:  y[n] = Σ x[k]h[n−k] = (x∗h)[n].
Where the argument would break

Every step used exactly one property. Drop time-invariance and step 2 collapses: the response to δ[n−k] would be some new function hk[n] depending on k, and the best you get is y[n] = Σ x[k]hk[n] — a superposition sum, not a convolution. Drop linearity and step 3 collapses entirely; there is then no formula at all. Convolution is not a general fact about systems. It is precisely the privilege of being LTI.

The continuous-time version

Same three steps, with the sum becoming an integral.

Slice a continuous signal into narrow rectangles of width Δ. Each slice is roughly an impulse of area x(kΔ)·Δ. Let Δ → 0 and the sum becomes an integral:

x(t) = ∫−∞∞ x(τ)·δ(t − τ) dτ   ⟹   y(t) = ∫−∞∞ x(τ)·h(t − τ) dτ

The procedure is unchanged — reflect h(τ) → h(−τ), shift it to t, multiply, and now integrate the overlap instead of summing it. The only new difficulty is bookkeeping: the limits of integration change as the sliding window enters, fully covers, and leaves the other signal, so you must split the answer into ranges of t.

Canonical example — rect ∗ rect = triangle

Let x(t) = h(t) = 1 on [0, 1] and 0 elsewhere. Then:

  • t < 0: no overlap → y = 0
  • 0 ≤ t < 1: overlap length t → y = t
  • 1 ≤ t < 2: overlap length 2 − t → y = 2 − t
  • t ≥ 2: no overlap → y = 0

A triangle of width 2, peak 1 at t = 1. Note the width added (1 + 1 = 2) — the continuous analogue of the N+M−1 length rule.

Second canonical example — step into an RC-like system

x(t) = u(t), h(t) = e−tu(t). For t ≥ 0:

y(t) = ∫0t 1·e−(t−τ) dτ = e−t∫0t eτ dτ = 1 − e−t

The classic charging curve. This is the continuous cousin of the geometric-decay echo of section 8, and the reason αⁿu[n] and e−atu(t) should feel like the same animal to you.

Two traps in continuous convolution
  • The integration variable is τ, not t. Inside the integral t is a constant. Students routinely integrate e−t with respect to t and lose everything.
  • The limits are set by the overlap, not by the formula's own limits. Draw the two pictures — x(τ) and h(t−τ) on a τ-axis — before writing any integral. Every mark in these questions lives in that sketch.

TypeWhat to write

The ten mistakes that cost marks

  1. Calling y = 2x + 3 linear.
  2. Proving linearity with one specific pair of signals instead of arbitrary ones.
  3. Forgetting to reflect before sliding — computing correlation instead of convolution.
  4. Getting the output's start index wrong. If x starts at −2 and h at 1, y starts at −1, not 0.
  5. Producing an output of the wrong length (should be N + M − 1).
  6. Substituting t → t − t₀ in only some of the places t appears.
  7. Assuming linear ⟹ time-invariant (or the reverse). They are independent.
  8. Integrating over t instead of τ in continuous convolution.
  9. Using a single set of integration limits across all ranges of t.
  10. Applying convolution to a non-LTI system. The formula simply does not hold there.
Deeper questions to chew on
  • Convolution smears things out; can an LTI system ever sharpen a signal? (Consider h = {1, −1} — a differencing filter. Yes, but only by cancellation.)
  • Is there an LTI system that undoes a given one? That would need h ∗ hinv = δ — an inverse system. Try it for the delay (easy) and then for h = u[n] (answer: the differencer δ[n] − δ[n−1]).
  • Why does the impulse work as a probe at all? Because it contains "all frequencies equally" — a claim you can only really justify after Fourier, in Lecture 5. Keep the question warm.
  • Convolving two length-N sequences costs O(N²) multiplications. The FFT will reduce this to O(N log N) — one of the most consequential algorithms of the twentieth century, and it exists precisely because of the polynomial identity in section 5.

One-line summary of the lecture

An LTI system is completely described by its impulse response, and the output for any input is the convolution of the input with that impulse response.
