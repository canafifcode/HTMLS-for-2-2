01 · Why grammars?

From recognizing to generating

A finite automaton asks "is this string accepted?" A grammar asks something more ambitious: "how could this string be built?" That shift — recognizer to generator — is what unlocks recursive structure.

The recursion problem

A DFA reads input left to right with a fixed, finite amount of memory — its states. That's precisely why no DFA can check whether parentheses are balanced: balancing requires counting, and counting requires memory that grows with the input. Nested brackets, function calls, and mirrored packets all share one structural idea:

The core pattern
A large valid object contains a smaller valid object of the same kind.

Nested brackets

([]{()}) — a valid object may contain a smaller valid object.

Function calls

encrypt(hash(msg)) — an argument may itself be a call.

A grammar before the definition

Balanced parentheses — ε, (), ()(), (()), (()()), ((())()) — are generated by three compact rules:

S → SS | (S) | ε
  • S → ε — the empty string is trivially balanced.
  • S → (S) — wrapping a balanced string keeps it balanced.
  • S → SS — concatenating two balanced strings keeps it balanced.

Interactive: derive (()())

Step through the construction history one rule application at a time.

Key intuition
A CFG has only finitely many rules, but recursion lets those rules be reused arbitrarily many times — that's how a finite description generates infinitely many strings.
02 · Formal definition

The 4-tuple, precisely

Every CFG is a 4-tuple G = (V, Σ, R, S). Getting comfortable naming each part is what lets you read (and write) grammars fluently for the rest of the course.

V — variables

Finite set of nonterminals; placeholders for structure not yet expanded (S, E, T, F).

Σ — terminals

Finite set of actual output symbols, disjoint from V (0, 1, +, (, )).

R — productions

Finite set of rules A → α, where A ∈ V and α ∈ (V ∪ Σ)*.

S — start symbol

The single variable in V where every derivation begins.

A rule A → α means: wherever A appears in the current sentential form, replace that occurrence with α. A derivation succeeds once every variable is gone — written S *⇒ w for w ∈ Σ*.

What "context-free" actually means
The rule for rewriting A never depends on what surrounds that occurrence of A. Context-sensitive grammars can condition a rule on neighboring symbols — CFGs never get that privilege. That restriction is exactly what makes CFGs tractable to parse.

Sentential forms and the language of a grammar

Any string over variables-and-terminals that appears mid-derivation is a sentential form. For S → 0S1 | #:

StepSentential form
0S
10S1
200S11
300#11

The language of G is everything reachable this way: L(G) = {w ∈ Σ* | S *⇒ w}. A language is context-free if some CFG generates exactly it.

Grammar ≠ language
A grammar is a description; a language is the set it describes. Two different-looking grammars can generate the very same language — you'll see this explicitly when we fix ambiguity in the expression grammar later.

A recursive worked example

Nested commands like encrypt(sign(data)):

S → D | F(S) F → hash | sign | encrypt D → data | msg | key

"A command is either raw data, or a function applied to a smaller command." Base case + wrap a smaller instance — this is the single most reusable idea in the whole lecture.

Leftmost vs. rightmost derivations

When a sentential form has several variables at once, you must choose which to expand next:

  • Leftmost (⇒lm) — always expand the leftmost variable.
  • Rightmost (⇒rm) — always expand the rightmost variable.

Using E → E+T | T, T → T*F | F, F → (E) | a, both orders eventually derive a+a*a — they differ in which intermediate sentential forms appear, not in the final tree. This matters later: leftmost derivations correspond to top-down (LL) parsing, rightmost (reversed) to bottom-up (LR) parsing.

Quick check: in the rule A → α, what must be true of α?
α must contain only terminals
α must contain exactly one variable
α can be any string over V ∪ Σ, including empty
03 · Parse trees

From linear derivations to trees

A derivation is written as a sequence, but the object being built is hierarchical. The parse tree is that hierarchy made visible — and it's the picture that makes ambiguity obvious later.

Formal conditions

  • The root is labeled by the start variable S.
  • Every internal node is labeled by a variable.
  • Every leaf is labeled by a terminal or by ε.
  • If an internal node A has children (left to right) X₁, X₂, …, Xₖ, then A → X₁X₂⋯Xₖ must be a production of the grammar.

Special case: a node using A → ε has exactly one child, labeled ε.

Yield

The yield is the leaves read left to right, ignoring any ε-leaf. For S → SS | (S) | ε deriving (()), the yield is exactly the string (()) — the tree is a construction certificate for the string.

The equivalence that ties it together
For every variable A and terminal string w, these are all equivalent: (1) A *⇒ w, (2) A *⇒lm w, (3) A *⇒rm w, (4) there is a parse tree with root A and yield w. Derivations and parse trees carry exactly the same information — just packaged differently.

Reading a tree two ways

Top-down

Start from S, expand variables, try to generate the input. This is how you build a derivation by hand.

Bottom-up

Start from small substrings and infer which variables could have generated them. This is the CYK algorithm's approach.

Worked example: encrypt(sign(data))

Using S → D | F(S), F → hash|sign|encrypt, D → data|msg|key, the derivation and its tree describe the same object — the tree just makes the nesting visually obvious: encrypt wraps sign wraps data.

If a node labeled E has children E, +, T (left to right), which production must exist?
E → T
E → E + T
T → E + E

05 · Ambiguity

When one string has two stories

A string is derived ambiguously if it has two or more different parse trees — equivalently, two or more different leftmost (or rightmost) derivations. A grammar is ambiguous if it generates at least one string ambiguously.

Ambiguity is about the grammar, not the language
The same language may have both ambiguous and unambiguous grammars. Fixing ambiguity means finding a better grammar for the same L, not changing L itself.

Case 1 — operator precedence

E → E + E | E * E | (E) | a lets a+a*a parse as either a+a*a (times binds first) or a+a*a (plus binds first) — the grammar treats + and * as structurally equal, so it fails to encode precedence.

Fix: introduce levels — factor, term, expression:

E → E + T | T T → T * F | F F → (E) | a

Multiplication is now forced below addition in the tree, so * always binds tighter than +.

Case 2 — the dangling else

A naive statement grammar S → if E then S | if E then S else S | other lets if E then if E then other else other attach the else to either the inner or outer if.

Fix: separate matched (M) and unmatched (U) statements:

S → M | U M → other | if E then M else M U → if E then S | if E then M else U

Convention encoded: every else attaches to the nearest unmatched if.

Case 3 — even balanced brackets can be ambiguous

S → SS | (S) | ε correctly generates balanced parentheses, but it's ambiguous: ()()() can be grouped as ()·()·() in more than one way via the SS rule.

Lesson
A language can have an "obviously correct" grammar that is still ambiguous. Correctness (generating the right language) and unambiguity (one tree per string) are separate properties.

Inherent ambiguity

Some languages are worse off: a CFL L is inherently ambiguous if every CFG for L is ambiguous — no amount of rewriting fixes it. The standard example:

L = {aⁿbⁿcᵐdᵐ | n,m≥1} ∪ {aⁿbᵐcᵐdⁿ | n,m≥1}

Strings of the form aⁿbⁿcⁿdⁿ belong to both halves of the union, so they're always derivable via two structurally different branches — that's unavoidable.

A grammar is ambiguous if...
it can't generate every string in its language
at least one string it generates has two or more distinct parse trees
it has more than one start variable
06 · Pumping lemma

Proving a language is NOT context-free

Context-free grammars are powerful but bounded. The pumping lemma gives a necessary property every CFL must satisfy — violate it, and the language cannot be context-free.

The statement
If L is context-free, there's an integer p ≥ 1 (the pumping length) such that every w ∈ L with |w| ≥ p can be written w = uvxyz where: (1) |vxy| ≤ p, (2) |vy| > 0, (3) for every i ≥ 0, uvⁱxyⁱz ∈ L.

Who chooses what

Our choices

A witness string w (usually built from p), and a pumping value i (typically 0 or 2).

Adversary's choice

The decomposition w = uvxyz — subject only to |vxy| ≤ p and |vy| > 0. A proof must handle every valid decomposition.

Standard proof template

  1. Assume, for contradiction, that L is context-free.
  2. Let p be the pumping length.
  3. Choose a witness w ∈ L with |w| ≥ p.
  4. Consider an arbitrary valid decomposition w = uvxyz; use |vxy| ≤ p to restrict where v and y can sit.
  5. Choose a pumping value i; show uvⁱxyⁱz ∉ L for every possible placement.

Choosing a good witness

Required propertyTypical witness
Three equal blocksa^p b^p c^p
Two crossing equalitiesa^p b^p c^p d^p
Prime lengtha^q, q > p prime
Nonlinear relationshipa^p b^(p²)
What the lemma does NOT prove
L violates the pumping property ⟹ L is not context-free. But showing a few strings can be pumped never proves L is context-free — for that you need an actual grammar or PDA.

Proof checklist

  • Assumed L is context-free, for contradiction
  • Let p be an arbitrary pumping length
  • Witness w is actually in L, and |w| ≥ p
  • Considered an arbitrary valid decomposition
  • Used both |vxy| ≤ p and |vy| > 0
  • Covered every possible placement of vxy
  • Explicitly chose a pumping value i
  • Proved the pumped string is outside L, for every case
07 · Practice problems

Try these before the exam

Straight from the lecture's problem set. For each, specify the witness, characterize every possible location of vxy, choose a pumping value, and state exactly which language condition fails.

  1. {0ⁿ1ⁿ2ⁿ | n ≥ 0}
  2. {aⁿbᵐcⁿdᵐ | n,m ≥ 0}
  3. {aⁿb²ⁿc³ⁿ | n ≥ 0}
  4. {a^q | q is prime}
  5. {aⁿb^(n³) | n ≥ 0}
Two common proof mistakes to avoid
Fixing the decomposition yourself — you never control where v and y land; the adversary does. And pumping only one piece — the lemma pumps both v and y together (uvⁱxyⁱz), so their combined effect on symbol counts is what determines the contradiction.

Where CFGs hit their ceiling

The pumping lemma shows CFGs structurally cannot maintain: three simultaneous equal block lengths, crossing equality constraints, prime-length requirements, or nonlinear counting relationships. That's precisely the gap that pushdown automata (single-stack memory) will turn out to match exactly — our next lecture.

08 · Exam mastery

Edge cases examiners actually test

The definition looks simple until a question exploits one of its corners. These are the corners that come up over and over — know them cold.

Corner 1 — α can be empty

In A → α, α ranges over (V ∪ Σ)* — which includes the empty string. A → ε is completely legal, and it's exactly how recursion terminates (recall S → ε in balanced brackets).

Corner 2 — recursion is required for an infinite language

Exam trap
"Give a CFG with no recursive productions that generates an infinite language." This is impossible — a finite set of non-recursive rules can only ever build finitely many distinct terminal strings. Proof sketch: without any variable capable of reappearing beneath itself, every derivation tree has bounded depth, so there are only finitely many distinct trees, hence finitely many yields.

Corner 3 — useless symbols

A grammar can contain a variable that's syntactically fine but contributes nothing to L(G):

Unreachable

No derivation from S ever reaches it — it never appears on the right side of any rule reachable from S.

Unproductive

It can never derive an all-terminal string — e.g. B → B with no alternative is an infinite dead end.

The removal algorithm needs two passes, in this order:

  1. Bottom-up: mark every variable that can derive some terminal string; discard the rest.
  2. Top-down: mark every variable reachable from S in the reduced grammar; discard the rest.
Order matters
Doing only one pass can leave a variable that's reachable but still unproductive, or productive but unreachable. Both passes are required, in this order, to fully simplify.

Worked exam problem

Give a CFG for L = {aⁱbʲcᵏ | i = j+k}, and give a leftmost derivation for aabc.

The mistake most students make here
Reaching for S → aSb | aSc | ε looks tempting since each step "spends" one a against one b or c — but it interleaves a's with b's and c's arbitrarily, generating strings like abac. That violates the required block shape a...a b...b c...c. Matching a count equality without checking block order is the single most common error on this style of question.

Correct design: nest one wrapping layer for the c-matched a's around a second wrapping layer for the b-matched a's, so all a's stay together as one contiguous block:

S → aSc | T T → aTb | ε

S contributes p pairs of (a,c) from the outside in; T contributes q pairs of (a,b) in the middle. The result is always a^(p+q) b^q c^p — one contiguous a-block, then b's, then c's — with i = p+q = q+p = j+k automatically.
