01 · Why a stack?

The smallest extension that adds memory

Today's question: what's the smallest useful extension of a finite automaton that can remember an unbounded amount of structured information? The answer is one unbounded, last-in-first-out stack.

The first target language

Take A = {0ⁿ1ⁿ | n ≥ 0}. A recognizer must remember how many 0s appeared, then verify the same number of 1s follows.

A DFA has

Finitely many states, no growing memory, no way to store an arbitrary n.

A stack can

Push one marker per 0, pop one marker per 1, detect mismatch or wrong order.

A stack is last-in, first-out

Two operations only: push (place a symbol on top) and pop (remove the top symbol). Only the top symbol is ever directly accessible — you cannot peek or modify anything beneath it.

The PDA architecture

A pushdown automaton is roughly an NFA equipped with a stack. At each step, the machine consults three things at once: current state, next input symbol (or ε), and top stack symbol (or ε).

Running strategy for 0ⁿ1ⁿ

  1. While reading 0s, push one 0 onto the stack for each input 0.
  2. When the first 1 arrives, switch to a popping phase.
  3. For every input 1, pop one stack 0.
  4. Accept only when the entire input is consumed and the stack is empty.
Mental picture
The stack height records exactly #0s read − #1s read at every point in the computation.

Interactive: trace on 000111

How bad strings fail

001

Input ends while a 0 still remains on the stack — unmatched, so rejected.

011

The PDA needs to pop after the stack is already empty — no legal move.

0101

After entering the 1-phase, a later 0 has no legal transition available.

General rule

A PDA rejects when every possible computation branch fails to accept.

02 · Formal definition

The 6-tuple, and what δ actually returns

A PDA is P = (Q, Σ, Γ, δ, q₀, F). Five of the six pieces are familiar from NFAs — the new piece, Γ, is the entire point of this lecture.

Q, q₀, F — finite control

States, start state, accept states — exactly as in an NFA.

Σ — input alphabet

Symbols that may appear in the input.

Γ — stack alphabet

Symbols that may be stored on the stack — can overlap Σ or be entirely different bookkeeping symbols.

δ — transition function

Tells the PDA which input symbol to read (if any), which stack symbol to pop (if any), which state to enter, and which symbol to push (if any).

δ : Q × Σε × Γε → P(Q × Γε) where Σε = Σ ∪ {ε} and Γε = Γ ∪ {ε}
Why the power set P(...)?
δ returns a SET of possible moves, not a single move — a PDA is generally nondeterministic. If (r, Y) ∈ δ(q, a, X), the machine may move q→r, read a (unless a=ε), pop X (unless X=ε), and push Y (unless Y=ε) — all as one legal option among possibly several.

Four common types of transitions

PopPushEffect
XYreplace X by Y
Xεpop X
εYpush Y
εεleave the stack unchanged

Example: (r,ε) ∈ δ(q,1,0) means "while in q, read a 1, pop a 0, move to r." And (r,0) ∈ δ(q,0,ε) means "while in q, read a 0, push a 0, move to r."

The three roles of ε

PositionMeaning
input = εchange state/stack without consuming input
pop = εdo not inspect or remove the current stack top
push = εdo not place a new symbol on the stack
Common confusion
ε is an INSTRUCTION meaning "do nothing here" — it is never a literal symbol stored in the input or on the stack.

Why a separate stack alphabet?

Σ and Γ serve different purposes: Σ is what can appear in the input, Γ is what can be stored as memory. For L={0ⁿ1ⁿ}, a natural choice is Σ={0,1}, Γ={0,$} — a 0 is pushed for every input 0, popped for every input 1, and $ marks the bottom of the stack.

Do we need a bottom-of-stack symbol?

A special symbol like $, ⊥, or Z₀ at the bottom lets the PDA detect when all previously stored symbols have been removed — reaching it again means the useful part of the stack is empty.

Edge case — exam favorite
A bottom marker is a convenient DESIGN CHOICE, not a required component of Sipser's formal definition. Don't claim it's mandatory on an exam.
Quick check: (r, Y) ∈ δ(q, a, X) with a=ε and X=ε. What does this transition do?
Reads a from input and pops X
Moves q→r and pushes Y, without reading input or popping anything
Rejects immediately
03 · Tracing computations

Configurations, steps, and acceptance

A configuration is the PDA's complete instantaneous snapshot. Chaining configurations together is how you trace — and verify — a computation by hand.

Configurations

(q, w, s) q = current state w = unread part of the input s = current stack content, top written on the LEFT

Example: (qpop, 11, 00) means the PDA is in state qpop, still has "11" left to read, and has two 0s on its stack.

One computation step

If (r,c) ∈ δ(q,a,b), then (q, aw, bs) ⊢ (r, w, cs)

Interpreted naturally when a component is ε: a=ε means no input symbol disappears; b=ε means no stack symbol disappears; c=ε means no stack symbol is added.

Acceptance by final state

P accepts w if (q0, w, ε) ⊢* (qf, ε, s) for some qf ∈ F, some s ∈ Γ*
  1. The entire input must be consumed.
  2. At least one computation branch must finish in an accept state.
Alternative convention
Acceptance by empty stack is another standard convention — it recognizes exactly the same class of languages. We'll formalize the equivalence in a later lecture.

A complete worked PDA: A = {0ⁿ1ⁿ}

Three states suffice: qpush, qpop, qacc, with a direct ε-transition qpush→qacc handling the n=0 case (the empty string).

Every string in A is accepted

For 0ⁿ1ⁿ, the machine pushes exactly n markers, then pops exactly n markers, consuming all input and reaching qacc.

Every accepted string is in A

An accepting run must read only 0s while pushing, then only 1s while popping — each 1 cancels exactly one earlier 0, so the counts must match.

04 · Designing PDAs

Ten worked-out PDA examples

Every worked example below uses the label convention input, pop → push, and a bottom-of-stack marker Z, accepting by final state only once Z becomes visible again.

A practical design checklist — ask these first
  1. What information must survive for an unbounded distance?
  2. What exactly should each stack symbol mean?
  3. When does the machine push, and when does it pop?
  4. Is the phase boundary visible in the input, or must it be guessed?
  5. What malformed input orders should have no transition at all?
  6. How are ε and the empty input handled?
  7. Why can no string outside the language ever reach an accept state?

Summary of the ten patterns

05 · Why nondeterminism matters

Guessing what the input doesn't tell you

This is the PDA lecture's answer to "ambiguity" — not a flaw to fix, but a deliberate design tool for handling boundaries the input doesn't mark.

Even palindromes: B = {wwᴿ}

A natural plan: push symbols from the first half, switch modes at the midpoint, compare the second half against the stack. The difficulty: there's no delimiter telling us where the midpoint occurs.

Guess the midpoint

A nondeterministic PDA branches at every position — one branch keeps pushing, another guesses "the first half ends here" and begins popping.

Acceptance semantics
The input is accepted if ONE branch guesses the correct midpoint and every symbol comparison in that branch succeeds. A wrong guess is harmless — that branch simply gets stuck or rejects, and doesn't affect the others.
PDA for B = {wwᴿ}: push: 0,ε→0 1,ε→1 guess: ε,ε→ε (nondeterministic switch to matching phase) match: 0,0→ε 1,1→ε

One accepting branch for 0110: push 0, push 1, guess the midpoint (stack: 10), then match 1 against 1, match 0 against 0, accept. Other branches guessing too early or too late simply fail.

A delimiter removes the guess entirely

For C = {w#wᴿ}, the symbol # explicitly marks the midpoint: push everything before #, pop-and-compare everything after. No guessing needed — this is the deterministic cousin of the palindrome problem, and it's exactly why {w#wᴿ} is easier to design than {wwᴿ}.

Nondeterminism as union

Consider D = {0ⁱ1ʲ2ᵏ | i=j or j=k}. A PDA branches into two independent jobs: one verifies i=j and ignores the 2s; the other ignores the 0s and verifies j=k.

Key principle
Nondeterministic branching naturally implements a language union, L₁ ∪ L₂. The machine doesn't need to know in advance which condition holds — it branches, and accepts if at least one branch verifies its condition while consuming all input.
Why does {w#wᴿ} not require nondeterministic guessing, while {wwᴿ} does?
{w#wᴿ} is not context-free
# explicitly marks the midpoint, so the phase switch is triggered by input, not guessed
Both require guessing equally
06 · What one stack still can't do

The ceiling above pushdown automata

A PDA is strictly more powerful than a finite automaton — but it isn't all-powerful either. One stack buys you exactly one running comparison at a time.

DFA versus PDA

PropertyFinite automatonPushdown automaton
Memorycurrent state onlystate + unbounded stack
Accessfinite controltop of stack only
Typical powerlocal patternsnested / matched structure
Examplestrings ending in 010ⁿ1ⁿ, palindromes
Nondeterminismno extra language powerstrictly increases power over deterministic PDAs

The language that breaks one stack

Consider {0ⁿ1ⁿ2ⁿ | n≥0}. This cannot be recognized by any one-stack PDA.

Intuition, not yet a proof
After using the stack to compare the 0s with the 1s, that stack has been consumed doing exactly that job — there's no independent leftover memory to also compare the same n against the 2s. One LIFO structure can only maintain one running comparison at a time. A formal impossibility proof (the PDA/CFL pumping lemma) comes in a later lecture.

08 · Exam mastery

Edge cases and common mistakes

The mistakes that recur most often when students design their first few PDAs — and the precise wording examiners look for.

Common mistakes

MistakeWhy it's wrong
Accept as soon as stack is emptyeven though unread input may still remain — both conditions are required together
Forgetting n=0the empty string is a valid case whenever the language allows it
Popping without checkinga symbol must actually match before popping, or the machine accepts wrong strings
Wrong symbol order permitteda transition that's too permissive lets malformed input reach accept
Misreading nondeterminismit means "accept if SOME branch succeeds," not "try one arbitrary choice"
Confusing ε with a symbolε is an instruction ("do nothing here"), never a literal stored symbol

Worked exam problem

Design a PDA (informally) for L = {aⁱbʲcᵏ | i=j or j=k}, and explain why nondeterminism is essential here.

The trap
Trying to build ONE deterministic machine that checks both conditions at once fails — by the time the c's arrive, a single stack has already been used up verifying (or not verifying) i=j against the b's, leaving no way to also independently verify j=k.

Correct approach — branch into two independent sub-machines at the start:

Branch 1 (verifies i=j): push X per a; pop X per b; ignore c's entirely Branch 2 (verifies j=k): ignore a's entirely; push Y per b; pop Y per c

The whole PDA accepts a string iff at least one branch both verifies its equality AND consumes the entire input — nondeterminism is what lets both possibilities coexist in one machine without knowing in advance which one holds.

Traps at a glance

TrapWhy it bites
Claiming a bottom marker is requiredit's a design convenience, not part of Sipser's formal definition
Treating δ as a function, not a relationthe power-set codomain is what makes nondeterminism possible at all
Ignoring the "entire input consumed" clausean empty stack alone is never sufficient for acceptance
Assuming one stack can track two independent comparisonssee {0ⁿ1ⁿ2ⁿ} — one LIFO structure, one running comparison
