Regular Operations,
Closure & Kleene's Theorem

We have machines that compute. Now we need an algebra to describe what they compute. This is a complete, corner-to-corner study companion to Lecture 5 — from union, concatenation, and star all the way to the full DFA ⇄ NFA ⇄ Regex ⇄ GNFA lifecycle.

Part I

§0Today's Roadmap

This lecture follows the central arc of Sipser's treatment of regular languages, and it all points toward one repeating idea:

language operation ⇐⇒ machine construction
  1. Define the three regular operations.
  2. Prove regular languages are closed under them.
  3. Define regular expressions formally.
  4. Prove that regular expressions and finite automata have exactly the same power.

The goal is not to memorize constructions — it's to see the same idea resurface every single time.

Setting the stage

§1Languages as Sets

Recall that a language is simply a set of strings. Because languages are sets, we can combine them using ordinary set operations to build new, more complex languages. Fix an alphabet Σ:

ObjectMeaning
Σa finite set of symbols
wa finite string over Σ
εthe empty string
Σ*the set of all strings over Σ
A ⊆ Σ*a language over Σ

A regular operation takes one or more languages and returns another language. When we write A ∪ B, AB, or A*, we are talking purely about sets of strings — the machine comes later. That's an important separation to keep straight: a closure proof always answers "if the inputs have machines, can we build a machine for the output language?"

The algebra of languages

§2The Three Regular Operations

Let A and B be languages. Let Σ = {a, b} for the examples, with A = {good, bad} and B = {boy, girl}.

Operation 1

Union

A ∪ B = { x | x ∈ A or x ∈ B }

The union simply takes all strings from A and all strings from B and puts them into a single set.

A ∪ B = {good, bad, boy, girl}
Operation 2

Concatenation

A ◦ B = { xy | x ∈ A and y ∈ B }

Concatenation attaches a string from A to the front of a string from B, in all possible combinations. We often omit the circle and just write AB.

A ◦ B = {goodboy, goodgirl, badboy, badgirl}
Operation 3

Kleene Star

A* = { x1x2…xk | k ≥ 0 and each xi ∈ A }

Star is a unary operation — it attaches any number of strings in A together to form a new string. Because k can be 0, the empty string ε is always in A*, regardless of what A is. Let A = {ab, c}:

A* = {ε, ab, c, abab, abc, cab, cc, ababab, …}
A subtle but important fact

§3Why Star Always Contains ε

For a language A, the expression A* means "concatenate zero or more strings from A." Concatenating zero strings produces the empty string:

A* = {ε} ∪ A ∪ AA ∪ AAA ∪ ⋯

So ε ∈ A* for every language A — even the empty language.

This is why ∅* = {ε}, not ∅. Zero strings from an empty set is still a well-defined (empty) concatenation, and it still equals ε.
Naming the class

§4Regular Languages

Definition

A language is called a regular language if some DFA recognizes it.

Alternative definition: a language is regular if some NFA recognizes it.

Both definitions are valid — a DFA is trivially an NFA, and every NFA has an equivalent DFA (the powerset construction).

The big question this lecture answers: if we take two regular languages and apply a regular operation to them, is the result still regular?
A concept borrowed from algebra

§5What Is a Closure Property?

Definition

A collection of objects is closed under some operation if applying that operation to members of the collection always returns an object still in the collection.

Mathematical examples:

ℕ is closed under addition3 + 5 = 8 ∈ ℕ
ℕ is not closed under subtraction3 − 5 = −2 ∉ ℕ
The theorem that anchors Part II

§6Sipser's Closure Theorem

Theorem

The class of regular languages is closed under the regular operations: ∪, ◦, *.

Sipser proves this early because it becomes the bridge to regular expressions later in the lecture. The proof uses NFAs throughout, because ε-transitions make the constructions visually and formally simple.

Nondeterminism is not a side topic — it is the cleanest language-design tool available, and every closure proof below leans on it.
Part II

§7A Closure Proof Template

Most closure proofs in this lecture share the same rhythm. Watch this shape repeat in every proof below.

  1. 1
    Start with machines for the inputs

    Let N1 recognize A1 and N2 recognize A2.

  2. 2
    Describe the operation to simulate

    What must the new machine accept, in terms of what N1 and N2 do?

  3. 3
    Build a new finite automaton

    Usually by wiring N1 and N2 together with new states and ε-transitions.

  4. 4
    Argue both directions

    Every accepted string belongs to the target language, and every target-language string is accepted. For regular operations, the construction is usually the heart of the proof.

Proof 1 of 6

§8Closure under Union

Theorem

A₁ ∪ A₂ is regular

If A1 and A2 are regular, then A1 ∪ A2 is regular. Proof idea: M should accept w if either M1 accepts w or M2 accepts w. We could simulate both DFAs at once by tracking pairs of states — but nondeterminism gives a cleaner tool: just guess which machine will accept.

A new start state q₀ with ε-transitions to the start states of N₁ and N₂.

Formal construction

Let N1=(Q1,Σ,δ1,q1,F1) and N2=(Q2,Σ,δ2,q2,F2). Construct N=(Q,Σ,δ,q0,F) where:

Q = Q1 ∪ Q2 ∪ {q0},   F = F1 ∪ F2,   δ(q0,ε) = {q1,q2}

All old transitions are kept unchanged.

Proof 2 of 6

§9Closure under Concatenation

Theorem

A₁ ◦ A₂ is regular

Given w, we want to split it as w = xy with x ∈ A1 and y ∈ A2 — but we don't know where the split point is. NFA to the rescue: the machine guesses the split point, non-deterministically, at every accepting state of N1.

Every accept state of N₁ gets an ε-transition to the start state of N₂; N₁'s accept states stop being accepting.

Formal construction

N starts in the start state of N1 and accepts in the accepting states of N2. The key added transition:

δ(r,ε) ∋ q2   for every r ∈ F1

Interpretation: after reading a prefix x ∈ A1, the machine may jump into N2 and try to read the rest as y ∈ A2. For w = 001101, the guess might land at 00|1101, 001|101, or 0011|01 — a DFA would need to check all of these indirectly, but the NFA states the idea directly.

Proof 3 of 6

§10Closure under Star

Theorem

A* is regular

Given N1 for A, we need A* to accept sequences of strings from A — including zero of them, so we must also accept ε. When N1 finishes one string in A, it should non-deterministically loop back to the start to try reading another.

q₀ is a new accepting start state. It ε-jumps into N₁, and every old accept state ε-loops back to N₁'s start.

Formal construction

Let N1=(Q1,Σ,δ1,q1,F1). Create a new start state q0 that is also accepting:

Q = Q1 ∪ {q0},   F = F1 ∪ {q0},   δ(q0,ε) ∋ q1,   and δ(r,ε) ∋ q1 for every r ∈ F1

The new accepting start state accounts for exactly zero repetitions — i.e. ε.

What "correctness" actually means

§11Two Directions in a Correctness Proof

For a constructed machine N and target language L, a full proof requires both directions:

  • L(N) ⊆ L — the machine accepts nothing extra.
  • L ⊆ L(N) — the machine accepts everything required.

Example for union: if N accepts w, some branch went into N1 or N2 and was accepted there, so w ∈ A1 ∪ A2. Conversely, if w ∈ A1 ∪ A2, choose the branch that heads into whichever machine accepts it.

Proof 4 of 6 — the DFA-only trap

§12Closure under Complement

Definition

The complement of A, written A̅, is every string in Σ* that is not in A:   A̅ = Σ* \ A.

Theorem

A̅ is regular

Proof idea: if M recognizes A, build M′ that does the exact opposite — if M accepts, M′ rejects, and vice versa.

Formal construction

Let M=(Q,Σ,δ,q0,F) be a DFA recognizing A. Construct M′=(Q,Σ,δ,q0,F′), where the only change is which states accept:

F′ = Q \ F
Warning — this only works for DFAs. If you flip the accept states of an NFA, the result does not necessarily recognize the complement. An NFA accepts if any path reaches an accept state — flipping states doesn't invert that "any path" logic correctly.
The DFA must be complete first. Every δ(q, a) must be defined for every state q and symbol a. If a transition is missing, add a dead (rejecting) state and route the missing transition there — otherwise "getting stuck" is silently different from "ending in a non-accepting state," and the flip breaks.

Only the accept states change (q₁ → q₀). Every transition arrow stays exactly the same.

Proof 5 of 6 — two independent routes

§13Closure under Intersection

Definition

A ∩ B = { x | x ∈ A and x ∈ B }

Route 1

Product Construction

Let M1=(Q1,Σ,δ1,q1,F1) and M2=(Q2,Σ,δ2,q2,F2) be DFAs. Build M to run both simultaneously — its states are pairs:

  • States: Q = Q1 × Q2 = { (r1,r2) | r1∈Q1, r2∈Q2 }
  • Start state: q0 = (q1, q2)
  • Transitions: δ((r1,r2), a) = (δ1(r1,a), δ2(r2,a))
  • Accept states: F = F1 × F2 — a pair state is accepting only when both coordinates are accepting.

A product state (r,s) means: after the same input prefix, M₁ is in r and M₂ is in s — two programs run side by side.

Route 2

De Morgan's Laws

A faster route relies on what we already proved. Recall De Morgan's law for sets:

A ∩ B = A̅ ∪ B̅

We already showed closure under complement (twice) and union — so A̅ ∪ B̅ is regular, and its complement A ∩ B is therefore regular too. No new machine required.

Proof 6 of 6, part one — free from earlier work

§14Closure under Difference

Definition

A \ B = { x | x ∈ A and x ∉ B }

Theorem

A \ B is regular

Notice that A \ B is simply the intersection of A with the complement of B:

A \ B = A ∩ B̅

Since regular languages are closed under complement and intersection, they are automatically closed under difference. No new construction needed — this is a one-line consequence of two earlier proofs.

Proof 6 of 6, part two — arrows in reverse

§15Closure under Reverse

Definition

The reverse of w = c1c2…cn is wR = cn…c2c1. The reverse of a language is AR = { wR | w ∈ A }.

Theorem

AR is regular

Proof idea: if M accepts a string by reading it forwards, build a new machine that accepts by reading it backwards — simply reverse every arrow in the transition diagram.

  1. 1

    Reverse the direction of every transition arrow.

  2. 2

    The old start state becomes the new single accept state.

  3. 3

    Create a brand-new start state.

  4. 4

    Draw ε-transitions from the new start state to all of the old accept states.

Why build an NFA, not a DFA? Reversing arrows can turn a deterministic machine into a nondeterministic one — two reversed arrows on the same symbol might now leave the very same state.
Putting the toolkit to work

§16The Power of Closure Properties

Once closure properties are established, we can prove new languages regular without ever drawing a state diagram.

Example

Contains 101, but doesn't end in 11

Let L be the language of strings over {0,1} that contain 101 but do not end in 11. Is L regular?

  • L1 = { w | w contains 101 } — regular (a small DFA recognizes it).
  • L2 = { w | w ends in 11 } — regular.
  • L = L1 \ L2, and regular languages are closed under difference.
Yes, L is regular. The proof is modular: prove the small pieces regular, then combine them with a closure property. A second example: if A = strings containing 101 and B = strings of even length, then A ∩ B is regular too, for the same reason.
Part III

§17What Is a Regular Expression?

We use the regular operations to build up expressions describing languages, exactly as arithmetic operations (+, ×) build up expressions describing numbers.

Arithmetic(5 + 3) × 4 evaluates to 32
Language(0 ∪ 1)0* evaluates to: a 0 or 1, followed by any number of 0s

These expressions are called Regular Expressions (RE).

Two layers of meaning

§18Syntax Versus Semantics

A regular expression is a piece of syntax. Its meaning is a language. We write L(R) for the language described by regex R.

ExpressionSyntax?Language
0a symbol expression{0}
0*star expression{ε, 0, 00, 000, …}
0 ∪ 1union expression{0, 1}
Six rules, applied inductively

§19Formal Definition of a Regular Expression

R is a regular expression if R is one of:

  1. a, for some a in the alphabet Σ
  2. ε (the empty string)
  3. ∅ (the empty set)
  4. (R1 ∪ R2), where R1 and R2 are regular expressions
  5. (R1 ◦ R2), where R1 and R2 are regular expressions
  6. (R1*), where R1 is a regular expression

This tells us exactly what syntactic structures are valid — and it's the reason structural induction becomes the natural proof technique for anything involving regular expressions, later in this lecture.

What each rule means

§20The Semantic Definition L(R)

Sipser's definition is inductive — the language of R is defined recursively, mirroring the syntax rules exactly:

L(a) = {a}    L(ε) = {ε}    L(∅) = ∅
L(R1∪R2) = L(R1)∪L(R2)
L(R1R2) = L(R1)L(R2)
L(R1*) = L(R1)*
Conveniences, not extra power

§21Regular Expression Shorthands

The formal definition is intentionally small. In practice, these shorthands make expressions readable:

ShorthandMeaning
Σunion of all alphabet symbols
R+RR*
R?R ∪ ε
RkR concatenated with itself k times
[0-9]0 ∪ 1 ∪ ⋯ ∪ 9
The atoms

§22Base Cases Explained

Expression RLanguage L(R)
a{a}
ε{ε}
∅{ } — the empty set
Notice the distinction: ε represents the language containing one string (which happens to be empty). ∅ represents the language containing no strings at all.
Order of operations

§23Precedence of Operations

Just like BEDMAS/PEMDAS in algebra, regex operations have a strict order — highest to lowest:

  1. Star (*)
  2. Concatenation (◦, usually omitted)
  3. Union (∪)

0 ∪ 10* means 0 ∪ (1 ◦ (0*)) — not (0 ∪ 10)* and not (0 ∪ 1) ◦ 0*.

Reading regexes fluently

§24Five Worked Examples

Let Σ = {0, 1} throughout.

ExpressionLanguage, in English
0*10*strings containing exactly a single 1
Σ*1Σ*strings containing at least one 1
1*∅∅ — concatenating anything with ∅ yields ∅ (like multiplying by 0)
∅*{ε} — star always contains ε, even when the base set is empty
Σ*1Σ*1Σ*strings containing at least two 1s (three Σ* blocks: before, between, after the two chosen 1s)
Translating English → regex. "Every string ends in 00" → (0∪1)*00. "Strings of even length" → ((0∪1)(0∪1))*, i.e. (ΣΣ)* — pairs of symbols, repeated any number of times.
The single most common mistake

§25Common Mistake: ∅ Versus ε

These two symbols look similar and are never interchangeable:

SymbolLanguage# of strings
∅no strings0
εthe empty string only1
R∅ = ∅     Rε = R
Simplifying like algebra

§26Useful Regex Identities

For any regular expression R:

  • R ∪ ∅ = R
  • R ◦ ε = R
  • R ∪ R = R
  • (R*)* = R*
  • R ◦ ∅ = ∅
Part IV

§27The Big Picture

We now have three models on the table — DFA, NFA, and Regular Expressions — plus one bridge machine, the GNFA, used only to build the proof.

DFA and NFA convert freely into one another; the GNFA exists purely to bridge DFA and Regex. Kleene's Theorem is what guarantees the whole circle closes.

The unifying result

§28Kleene's Theorem

Theorem (Kleene)

A language is regular if and only if some regular expression describes it.

This splits into two independent lemmas, proved separately below:

  • Lemma 1: if a language is described by a regular expression, it is regular (it can be converted to an NFA).
  • Lemma 2: if a language is regular (recognized by a DFA), it can be described by a regular expression.
Direction one

§29Proof of Lemma 1: RE → NFA

We prove this by structural induction on the definition of a regular expression — the grammar from §19 tells us exactly which cases to handle.

  1. 1
    Handle the atomic expressions

    Build NFAs directly for the three base cases: R = a, R = ε, and R = ∅.

  2. 2
    Assume the smaller pieces are done

    Assume R1 and R2 already have NFAs — this is the inductive hypothesis.

  3. 3
    Build the three inductive cases

    Construct NFAs for R1∪R2, R1R2, and R1* — by simply plugging N1 and N2 into the exact same union, concatenation, and star constructions already proved in Part II.

This is why the closure proofs came first. No new machine-building ideas are needed here — this systematic translation from regex to NFA is often called Thompson's Construction, and it's just the closure proofs applied recursively.

The three base-case NFAs: a single a-labeled hop, an already-accepting single state, and an unreachable accept (nothing accepted).

Seeing the induction run

§30Worked Example: Converting (ab ∪ a)* to an NFA

  1. 1
    Build base NFAs

    One tiny NFA for a, one for b.

  2. 2
    Concatenate to get ab

    Wire an ε-transition from the accept state of the a-NFA to the start state of the b-NFA (the concatenation construction from §9).

  3. 3
    Union with a to get (ab ∪ a)

    Add a new start state with ε-transitions into both the ab-machine and a fresh a-machine (the union construction from §8).

  4. 4
    Apply star to the whole machine

    Wrap the result in the star construction from §10: a new accepting start state, plus ε-loops back from every accept state.

The finished (ab ∪ a)* NFA — two branches (ab and a) joined by union, then wrapped by star.

The takeaway. Every regular expression, no matter how complicated, can be built this way — one base case or one closure construction at a time. Nothing new is invented; the machine is just assembled from the pieces already proved.
Direction two — the harder half

§31Proof of Lemma 2: DFA → RE

If a language is regular, some DFA recognizes it. We need an algorithm converting that DFA into a regular expression — and for that we introduce a new machine.

Definition — GNFA

A Generalized Nondeterministic Finite Automaton is an NFA whose transitions are labeled by entire regular expressions, not just single symbols or ε. A transition from qi to qj labeled R means: the machine may travel from qi to qj by reading any block of input matching R.

δ : (Q \ {qaccept}) × (Q \ {qstart}) → 𝓡

where 𝓡 is the set of all regular expressions over Σ. Every allowed ordered pair of states has exactly one regex label; if there's no real way to move from p to q, that label is simply ∅.

The Strict Sipser Form

For the conversion algorithm to work cleanly, we force the GNFA into a strict shape:

  1. The start state has transitions going to every other state, but nothing comes in.
  2. There is a single accept state, with transitions coming in from every other state, but nothing goes out.
  3. The start state and accept state are different.
  4. Except for start and accept, exactly one arrow goes from every state to every other state — including from each state to itself.

Preparing a DFA for the Algorithm

  1. 1

    Add a new start state with an ε-transition to the old start state.

  2. 2

    Add a new single accept state with ε-transitions coming in from all old accept states.

  3. 3

    If any required transition is missing, add it with the label ∅.

  4. 4

    If a state has multiple parallel transitions to another state (say, on a and on b), combine them with union: a ∪ b.

Why bother with new start/accept states? They guarantee that exactly two states remain at the very end of the algorithm — and the single label left between them is the answer, with no extra case-handling required.

The Core Idea: State Ripping

Once in strict GNFA form, we successively remove ("rip") internal states one at a time, repairing the transitions between every remaining pair so the recognized language never changes. Eventually only the start and accept states remain — the single transition between them is the final regular expression.

The Ripping Formula

To rip state qrip, update the direct label between every remaining pair qi, qj:

Rnew(qi,qj) = Rold(qi,qj) ∪ ( R(qi,qrip) ◦ (R(qrip,qrip))* ◦ R(qrip,qj) )

In words: the old machine could go directly from qi to qj, or it could detour through qrip — possibly looping on qrip's self-transition any number of times along the way.

Ripping folds the detour through q(rip) — including any number of self-loops — directly into a single new label.

A useful reminder

§32Different Regexes Can Describe the Same Language

Regular expressions are not unique. For "strings ending in 1," all three of these describe exactly the same language:

  • (0 ∪ 1)*1
  • 0*1(1 ∪ 00*1)*
  • Σ*1
The GNFA algorithm gives a correct expression — not necessarily the prettiest one. Simplification afterward (using the identities from §26) is a separate, optional step.
Closing the lecture

§33Summary of Kleene's Theorem

  1. Regular expressions precisely define patterns, algebraically.
  2. Any RE converts into an NFA — using base structures and the closure constructions (Lemma 1, Thompson's Construction).
  3. Every NFA is equivalent to a DFA (powerset construction).
  4. Any DFA converts back into a regular expression — using the GNFA and state ripping (Lemma 2).
Therefore: DFAs, NFAs, and Regular Expressions all describe exactly the same class of languages — the regular languages. Every arrow in the "big picture" diagram closes the circle.
