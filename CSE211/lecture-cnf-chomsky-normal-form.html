Chomsky Normal Form

Every context-free grammar, no matter how tangled, can be reshaped into one of exactly two production shapes — without changing the language it describes. That reshaping is what makes parsing algorithmic. This companion walks the full conversion pipeline end to end, cross-checks it against Sipser's version of the theorem, and ends with a working CYK parser you can step through by hand.

Atif Hasan Rahman · adapted from Dr. Muhammad Masroor Ali BUET CSE Study companion
Foundations · 01

What CNF Actually Is

Start with the official definition, then spend real time on the two clauses students tend to skate past.

Definition — Chomsky Normal Form

A context-free grammar G = (V, Σ, R, S) is in Chomsky Normal Form if every rule in R has one of exactly two shapes:

  1. A → BC, where A, B, and C are each variables, or
  2. A → a, where A is a variable and a is a terminal,

and, further, G has no useless symbols.

Read that carefully — it is a closed list. Not "two variables or a variable-terminal pair," not "up to two variables." Exactly one of those two shapes, every single time. A rule like A → aB is not CNF. Neither is A → BCD. Neither is A → B. Every one of those gets fixed by the pipeline in this companion.

The second clause — no useless symbols — is the one people forget exists at all, because it doesn't show up in the two bullet points. It's easy to build a grammar where every rule is syntactically the right shape but some variable can never actually contribute to a derivation. That grammar is not in CNF by this definition, even though every individual rule looks fine in isolation. We'll define "useless" precisely in a moment.

The ε exception

Strictly, forms (1) and (2) can never produce the empty string — A → BC always yields at least two symbols eventually, and A → a always yields exactly one terminal. So if ε ∈ L(G), CNF makes exactly one accommodation: the rule S → ε is permitted, where S is the start variable — provided S never appears on the right-hand side of any rule in the grammar. This exception is not optional decoration; you'll need it precisely once, at the very end of the elimination pipeline, and only for the start symbol.

A quick self-test is worth more than another paragraph of definition. For each rule below, is it legal inside a CNF grammar on its own (ignoring whether the rest of the grammar is consistent)?

✓A → BCTwo variables on the right. Textbook shape (1).
✓A → aA single terminal. Textbook shape (2).
✗A → aBMixes a terminal with a variable — neither shape allows this.
✗A → BCDThree variables. Shape (1) caps at exactly two.
✗A → BA unit production — a single variable is neither shape.
✗A → εIllegal unless A is the start symbol and it never appears on any right-hand side.
✓S → εLegal only under the special exception above — and only ever this one rule, for the start symbol.
Foundations · 02

Why We Bother

Normal forms always trade uniform shape for something in return. Here's what CNF buys.

Look at what CNF's two shapes guarantee about a derivation tree once you draw one out: every internal node has exactly two children (from rule shape 1), and every leaf hangs directly off a node that has no other children (from rule shape 2). In other words, a CNF derivation tree is always — no exceptions, no special cases — a proper binary tree with terminals only at the leaves.

That regularity is the entire reason the CYK algorithm (coming later in this companion) can exist as a clean dynamic-programming procedure. Ask "can some variable generate the substring from position i to position j?" and because every production is exactly binary, the answer only ever depends on splitting that substring at some point k and asking the same question about two strictly shorter pieces. Without CNF's guarantee, a rule like A → BCD would force you to consider two different split points simultaneously, and a rule like A → aBb would force you to align terminals against substring boundaries by hand. CNF removes all of that bookkeeping before the algorithm even starts.

Looking ahead — that same binary-tree guarantee is what eventually lets you bound a derivation's height against the length of the string it produces (a CNF tree of height h can generate a string of length at most 2^(h-1)). That bound is the load-bearing fact behind the Pumping Lemma for context-free languages — the direct CFL analogue of the DFA pigeonhole argument from Lecture 6. You don't need that yet, but it's worth knowing why this particular normal form, and not some other one, is the one everyone converts to first.

One honest caveat: normal forms are never free. Converting to CNF can multiply the number of variables in a grammar substantially — every long right-hand side spawns a cascade of fresh helper variables, and every rule with a raw terminal mixed into a longer body spawns a terminal-isolating helper too. You're trading a messy-but-compact grammar for a uniform-but-larger one. That's the same trade DFA minimization makes in the other direction — structure for size — just on the opposite side of the ledger.

Foundations · 03

Aside — Noam Chomsky

A fair question: why is a linguist's name attached to a data structure fact about grammars?

Noam Chomsky is a linguist, philosopher, and cognitive scientist — often credited as the father of modern linguistics — best known in this course for formalizing the notion of a generative grammar: a finite set of rewriting rules capable of generating an infinite set of valid sentences. That formalism is exactly the context-free grammar you've been working with. Chomsky organized grammars into a nested hierarchy by expressive power — regular, context-free, context-sensitive, and unrestricted (recursively enumerable) — now simply called the Chomsky hierarchy, and it's the same hierarchy underlying the entire arc of this course: DFAs and regular expressions sit at the bottom, CFGs and pushdown automata sit one level up, and Turing machines sit at the top.

Chomsky Normal Form is one of several canonical rewritings named after him because it operates directly on his CFG formalism — it says nothing about natural language specifically, but the vocabulary (variables, terminals, productions, derivations) is inherited straight from his original notation.

Foundations · 04

Generating & Reachable

The vocabulary behind "no useless symbols" — and a genuine trap in how you check it.

A symbol earns its place in a grammar by doing two separate jobs. Missing either one makes it useless, no matter how legitimate its rules look.

Two conditions for usefulness

Generating. A variable X is generating if X ⇒* w for some string of terminals w. Every terminal is trivially generating — it already is a terminal string.

Reachable. A variable X is reachable if there's some derivation S ⇒* αXβ — meaning X genuinely shows up somewhere along some path that starts from the actual start symbol.

A symbol is useless exactly when it fails at least one of these — either it can never bottom out into terminals, or the start symbol can never reach it in the first place.

Worked example

S → AB | a,   A → b

Find and remove every useless symbol.

  • 1 Check generating, first

    B has no rules at all — nothing tells you what B ever rewrites to. It cannot be generating. Every rule that mentions B is now dead weight too, so S → AB is deleted along with it.

    Remaining:   S → a     A → b
  • 2 Check reachable, second — on the reduced grammar

    Now ask what's reachable from S in this smaller grammar. S's only surviving rule is S → a, which never mentions A. So A is unreachable, even though it looked perfectly fine a moment ago. Delete A → b.

    Final grammar:   S → a
Why the order is not a stylistic choice: generating-ness can only be lost by removing rules, so it has to be computed on the original grammar (or recomputed to a fixed point). Reachability, on the other hand, should be checked last, on whatever's left after non-generating symbols are already gone — otherwise you can be fooled into keeping a symbol that was reachable in the original grammar but only through a path that's since been deleted.
Trap — reachable-then-generating can silently fail
  • Run it backwards on the same grammar: check reachability first. From S, both A and B are reachable (via S → AB and S → a) — nothing gets removed at this stage, since nothing looks unreachable yet.
  • Then check generating: B still has no rules, so it's removed, and S → AB is deleted with it. So far so good — but if you stop here after a single pass of each check, you've been fooled: A → b is still sitting in the "cleaned" grammar, even though A is now unreachable in the grammar you actually ended up with.
  • The fix isn't "do generating first" as a magic incantation — it's that generating-ness is a closure property of the original rule set, while reachability has to be evaluated on the final rule set. Doing generating first and reachable last, in that order, in a single clean pass, gets you there directly. Doing it the other way around demands a second reachability pass to catch what the generating-removal step exposed.
Part II — The Conversion Pipeline
Pipeline · Overview

The Four-Step Roadmap

Every CNF conversion, no matter the grammar, runs the same four stages, in this order. Order matters — each stage assumes the previous ones are already done.

  1. i
    Eliminate ε-productions

    Find every nullable variable, then rewrite every rule that mentions one to cover both "it's there" and "it vanished." Discard the literal A → ε rules once their effect is baked in everywhere else.

  2. ii
    Eliminate unit productions

    A rule like A → B just renames — it contributes no actual structure. Compute which variables reach which other variables through chains of unit rules, then copy the real (non-unit) productions across those chains directly.

  3. iii
    Eliminate useless symbols

    Steps i and ii can leave dead weight behind — a unit chain that dead-ends, a variable nothing points to anymore. Re-run the generating-then-reachable check from the previous section on the grammar as it now stands.

  4. iv
    Convert to CNF form — TERM, then BIN

    Every remaining rule body is either a single terminal (already fine) or a mix of variables and terminals of some length. TERM isolates any raw terminals in multi-symbol bodies behind fresh helper variables. BIN then breaks any body still longer than two symbols into a cascade of binary rules.

A note on convention — this course vs. Sipser

Sipser's version of this theorem (§2.1) begins with an extra step: introduce a brand-new start symbol S₀ with the single rule S₀ → S, before touching anything else. That guarantees the true start symbol can never re-appear on the right-hand side of any rule — which is exactly what lets the later ε-elimination step safely except only S₀ from having its ε-rule deleted, with no risk of accidentally exempting a variable that shows up elsewhere in the grammar. Sipser also doesn't carry "eliminate useless symbols" as a labeled step inside the same theorem — it's proven once, earlier, as its own standalone simplification result, and just assumed available here.

This course's ordering (following Hopcroft–Ullman) folds useless-symbol elimination directly into the same four-step pipeline instead, and skips the extra S₀. In practice the two approaches land on equivalent grammars almost always. The gap only matters when your original start symbol already appears on some right-hand side (for instance S → aSb) — that's precisely the case Sipser's S₀ trick is built to protect against. Keep this in your back pocket: if a solution manual's CNF grammar has one more variable than yours, this is often exactly why.

Pipeline · Step i

Kill the ε's

Nullable variables are the ones that can quietly disappear. Before you can outlaw ε-rules, you have to account for every place their disappearance was doing real work.

Definition — nullable

A variable A is nullable if A ⇒* ε. This includes the direct case (A → ε is a rule) and the indirect case (A's entire body consists of variables that are themselves — recursively — all nullable).

The substitution rule

Once you know the full set of nullable variables, go rule by rule. For any rule whose body contains k occurrences of nullable variables (occurrences, not distinct variables — a repeated variable counts each time it appears), generate every way of independently keeping or dropping each of those k occurrences — that's 2^k candidate bodies. Discard exactly one candidate: the one where every symbol in the body got dropped, leaving nothing. Never re-add that empty case as a new rule.

Finally, throw away the original literal A → ε rules — their job is done once every rule that referenced A has been expanded to cover its disappearance.

One exception, applied once, at the very end: if the start symbol itself turned out to be nullable — meaning ε ∈ L(G) — add back exactly S → ε.

Worked example

S → AB,   A → aAA | ε,   B → bBB | ε

  • 1 Find every nullable variable

    A and B are nullable directly (A → ε, B → ε). Then S → AB has a body made entirely of nullable variables, so S is nullable too. All three variables are nullable.

  • 2 Expand S → AB

    Two occurrences, both nullable: A (keep/drop) × B (keep/drop) → 4 combinations: AB, A, B, and ε. Drop the empty one.

    S → AB | A | B
  • 3 Expand A → aAA

    The body is a A A — the terminal a is never dropped, and the two A occurrences (positions 2 and 3) are each independently nullable. 2² = 4 combinations: keep both → aAA; drop position 2 → aA; drop position 3 → aA; drop both → a. Note the middle two combinations are different choices that happen to produce the same string — that's not an error, it's a genuine coincidence of which position you deleted.

    A → aAA | aA | aA | a   (the repeated aA is harmless to merge into one)
  • 4 Expand B → bBB, symmetrically
    B → bBB | bB | bB | b
  • 5 Discard the literal ε-rules, then check the start symbol

    A → ε and B → ε are both discarded now. S came out nullable in step 1, so ε ∈ L(G) — add S → ε back, once.

    Final:   S → AB | A | B | ε     A → aAA | aA | a     B → bBB | bB | b
Trap Museum — ε-elimination
  • Skipping the empty-body exclusion. If a rule's entire body is nullable variables, dropping all of them is exactly how you'd re-derive A → ε — which is precisely what you're trying to eliminate. Always discard that one combination.
  • Treating repeated occurrences as one choice. aAA has two independent decisions to make, not one — miss this and you'll silently lose the aA alternatives from the final grammar.
  • Re-adding X → ε for a non-start variable mid-algorithm. The ε-exception belongs to the start symbol, applied once, at the very end — never to an intermediate variable while you're still expanding other rules.
  • Distinct nullable variables in the same body still just need "all subsets." A body like XAYB with only A, B nullable (not X, Y) still gives 2² = 4 versions — XAYB, XYB, XAY, XY — never touching the non-nullable symbols.
Pipeline · Step ii

Kill Unit Rules

A rule A → B doesn't build anything — it just says "whatever B can do, A can do too." CNF has no room for pure relabeling, so it gets compiled away.

Definitions

Unit production: a rule of the exact form A → B, where both A and B are variables.

Unit pair (A, B): A ⇒* B using only unit productions along the way — a chain A → X₁ → X₂ → … → B. Every variable forms a trivial unit pair with itself, (A, A), using zero steps.

The algorithm

Compute the full reflexive-transitive closure of the unit-pair relation — treat the unit rules as directed edges on a graph over variables, and find every pair reachable from every other. This is a graph-reachability computation, not a rewriting process — don't substitute rules into each other by hand and hope it terminates.

Then, for every unit pair (A, B) you found, copy every non-unit production of B directly onto A. Once this is done for all pairs, discard every original unit rule — only the freshly copied non-unit bodies remain.

Worked example

The arithmetic-expression grammar

I → a | b | Ia | Ib | I0 | I1     F → I | (E)     T → F | T*F     E → T | E+T
  • 1 Trace the unit pairs

    Start from the trivial pairs (E,E), (T,T), (F,F), (I,I). Then follow the unit rules one hop at a time: E → T gives (E,T); from there T → F gives (E,F); from there F → I gives (E,I). Similarly (T,F) and (T,I) fall out of T → F → I, and (F,I) falls out of F → I directly.

  • 2 Copy non-unit productions across every pair
    PairProductions copied
    (E,E)E → E+T
    (E,T)E → T*F
    (E,F)E → (E)
    (E,I)E → a | b | Ia | Ib | I0 | I1
    (T,T)T → T*F
    (T,F)T → (E)
    (T,I)T → a | b | Ia | Ib | I0 | I1
    (F,F)F → (E)
    (F,I)F → a | b | Ia | Ib | I0 | I1
    (I,I)I → a | b | Ia | Ib | I0 | I1
  • 3 Union per variable, drop the original unit rules
    E → E+T | T*F | (E) | a | b | Ia | Ib | I0 | I1
    T → T*F | (E) | a | b | Ia | Ib | I0 | I1
    F → (E) | a | b | Ia | Ib | I0 | I1
    I → a | b | Ia | Ib | I0 | I1
Trap Museum — unit-production elimination
  • Naive repeated substitution loops forever on unit cycles. If a grammar had A → B and B → A, endlessly "substituting until no unit rules remain" never terminates. Computing the closure as a finite set of pairs first sidesteps this completely.
  • A pair can be legitimate and still contribute nothing. If B happens to have no non-unit productions at all — every one of its rules is itself a unit rule, chaining further — then (A,B) adds nothing to A. If that's true for an entire cluster of variables with no exit into a real production, every variable in that cluster is dead: this is exactly why unit-elimination and useless-symbol elimination are run back to back.
  • Forgetting the reflexive pairs. (A,A) matters — without it, A's own directly-attached non-unit productions (the ones it already had, not inherited from anywhere) can get dropped by mistake during bookkeeping.
Pipeline · Step iii

Kill Useless Symbols — Reprise

Same test as before — generating first, then reachable — just re-run now that ε- and unit-elimination have had a chance to change what's actually connected.

Steps i and ii can each create new dead ends that weren't obviously dead in the original grammar — most commonly, a unit-elimination pair that turned out to contribute nothing (the trap above). So step iii is exactly the check from the Foundations section, applied one more time, on the grammar as it stands right now.

Running it on both examples above: in the A, B-nullable grammar, every one of S, A, B is generating (each has a rule bottoming out in a pure terminal string) and reachable (all three are visibly connected from S). In the arithmetic grammar, I is generating via I → a, and that generating-ness climbs back through F, T, E; reachability runs the other way, from E down through T, F, I. Nothing new becomes useless in either case — both grammars pass through step iii unchanged. That won't always happen; it's worth checking explicitly rather than assuming it, every time.

Pipeline · Step iv

Convert to CNF — TERM & BIN

The last mile. Every surviving rule body is either already a lone terminal (fine, leave it), or some mix of terminals and variables of some length. Two clean-up passes finish the job.

TERM — isolate terminals

Scan every rule body of length ≥ 2 for raw terminal symbols. For each distinct terminal that shows up inside such a body anywhere in the whole grammar, introduce exactly one fresh helper variable for it — reused everywhere that terminal appears in a multi-symbol body, not re-created per occurrence — with a new rule NewVar → terminal. Replace every such occurrence with the helper. Bodies that are already a single lone terminal (A → a) are untouched — they're already valid.

BIN — binarize long bodies

Now every remaining multi-symbol body consists entirely of variables. Any body still of length ≥ 3 gets broken into a left-to-right cascade of fresh helper variables, each one standing in for exactly two adjacent symbols, until the head rule is down to two symbols.

Worked example

Finishing the arithmetic grammar

Picking up exactly where unit-elimination left off, over the alphabet {a, b, 0, 1, +, *, (, )}.

  • 1 TERM — eight terminals need helpers

    Every one of the eight terminals shows up inside some multi-symbol body somewhere in the grammar (E+T, T*F, (E), Ia, Ib, I0, I1). Introduce one helper per terminal:

    A → a   B → b   Z → 0   O → 1   P → +   M → *   L → (   R → )

    Replace every terminal occurrence inside a longer body with its helper — note I a becomes I A, I 0 becomes I Z, and so on, while the standalone single-terminal bodies (I → a, I → b) are left exactly as they are:

    E → EPT | TMF | LER | a | b | IA | IB | IZ | IO
    T → TMF | LER | a | b | IA | IB | IZ | IO
    F → LER | a | b | IA | IB | IZ | IO
    I → a | b | IA | IB | IZ | IO
  • 2 BIN — three bodies are still length 3

    EPT, TMF, and LER are each three variables long. Introduce one cascade helper per distinct length-3 body:

    C₁ → PT     C₂ → MF     C₃ → ER

    and rewrite each length-3 body as (first symbol) + (helper):

E → EC₁ | TC₂ | LC₃ | a | b | IA | IB | IZ | IO
T → TC₂ | LC₃ | a | b | IA | IB | IZ | IO
F → LC₃ | a | b | IA | IB | IZ | IO
I → a | b | IA | IB | IZ | IO
A → a   B → b   Z → 0   O → 1   P → +   M → *   L → (   R → )
C₁ → PT   C₂ → MF   C₃ → ER
Every body, checked: each of EC₁, TC₂, LC₃, IA, IB, IZ, IO is exactly two variables — shape (1). Each of a, b alone is exactly one terminal — shape (2). Fourteen variables total, up from four. That's the size-for-uniformity trade in action.
Trap Museum — TERM & BIN
  • Running BIN before TERM. Break a body like aBC into binary form first and you'd get a helper whose body is still a mixed with a variable — you'd just be re-creating the TERM problem one level down, and you'd need a second pass anyway. TERM first means BIN only ever sees pure-variable bodies.
  • Forgetting length-exactly-2 mixed bodies. A body like aB is already short enough that BIN wouldn't touch it — but it still violates TERM, since shape (1) requires both symbols to be variables. This is the single most common CNF-conversion mistake on an exam: fixing only the "obviously long" bodies and skipping the short mixed ones.
  • Minting a brand-new helper name that collides with an existing variable. Every helper — for TERM and for BIN — needs a genuinely fresh name. Reusing an existing variable's name silently merges two unrelated meanings into one.
Part III — Capstone
Capstone

Bridge to Sipser

Your primary text proves this exact theorem with its own running example. Let's push it through this lecture's four-step pipeline, end to end, and confirm it lands on a valid CNF grammar — good cross-training between the two treatments you're getting this term.

Note on method — what follows is derived live, rule by rule, rather than quoted from memory. Every intermediate grammar is checked (nullability by fixpoint, unit pairs by closure, generating/reachable explicitly), and the final grammar is cross-verified against two independent test strings at the end. Audit any step you like.
Running example

S → ASA | aB,   A → B | S,   B → b | ε

  • i Eliminate ε-productions

    Nullability, by fixpoint: B is nullable directly. A → B makes A nullable too. Does S become nullable? S → ASA would need S nullable to certify itself — circular, so it never gets marked; S → aB can't be nullable regardless, since it always contains the terminal a. So nullable = {A, B}, and S is not nullable.

    Expand each rule: S → ASA has nullable occurrences at positions 1 and 3 (the two A's), position 2 (S) is never nullable and always stays. Four combinations, none empty: ASA, SA, AS, S — and S → S is a do-nothing self-loop, dropped on sight. S → aB has one nullable occurrence (B): keep → aB, drop → a.

    S → ASA | SA | AS | aB | a

    A → B: dropping the only symbol would leave an empty body — skip it, keep A → B unchanged. A → S: S isn't nullable, unchanged.

    A → B | S

    B → b is untouched; B → ε is discarded outright. Since S is not nullable, no S → ε is added — this grammar does not generate ε.

    B → b
  • ii Eliminate unit productions

    Unit rules present: A → B, A → S. Closure of unit pairs: (A,A), (S,S), (B,B) trivially, plus (A,B) and (A,S) directly — no further hops exist (S and B have no unit rules of their own).

    Copy non-unit productions across each pair: (A,B) gives A → b. (A,S) gives A → ASA | SA | AS | aB | a (all five of S's bodies, none of them unit rules). S and B gain nothing new from their own reflexive pairs — they had no unit rules to begin with.

    S → ASA | SA | AS | aB | a
    A → ASA | SA | AS | aB | a | b
    B → b
  • iii Eliminate useless symbols

    Generating: S → a, A → b, B → b — all three bottom out directly. Reachable: S's own bodies mention A and B, so both are reachable. Nothing is useless — the grammar is untouched by this step. (Worth confirming explicitly, even when — as here — nothing changes.)

  • iv Convert to CNF — TERM, then BIN

    TERM: the only raw terminal sitting inside a multi-symbol body is the a in aB (appearing in both S and A). One helper covers it: U → a.

    S → ASA | SA | AS | UB | a    A → ASA | SA | AS | UB | a | b    B → b    U → a

    BIN: the only body still length 3 is ASA (in both S and A). One cascade helper covers the last two symbols: C₁ → SA, then ASA → A C₁.

Final CNF grammar
S → AC₁ | SA | AS | UB | a
A → AC₁ | SA | AS | UB | a | b
B → b
U → a
C₁ → SA
Every body, checked: AC₁, SA, AS, UB — two variables each, shape (1). a, b — one terminal each, shape (2). Five variables total, up from three.

Part IV — The CYK Algorithm
CYK · 01

The Triangular Table

This is the payoff. With a grammar guaranteed to be in CNF, membership testing — "is w ∈ L(G)?" — stops being a search problem and becomes a fill-in-the-table problem, solvable bottom-up in polynomial time.

Naively, checking membership means searching over derivations, and there's no obvious bound on how many you'd need to try. The Cocke–Younger–Kasami (CYK) algorithm sidesteps this entirely with dynamic programming, and it only works because CNF guarantees every non-terminal step is a clean binary split.

Definition

For a string w = a₁a₂…aₙ and a CNF grammar G = (V, Σ, R, S), define

X_ij = { A ∈ V  :  A ⇒* a_i a_{i+1} … a_j }

— the set of variables that can generate exactly the substring running from position i to position j, inclusive.

Base case & recurrence

Base case (substrings of length 1): X_ii is the set of variables A such that A → a_i is a production.

Recurrence (substrings of length ≥ 2): A ∈ X_ij exactly when there's some split point k with i ≤ k < j, a variable B ∈ X_ik, a variable C ∈ X_{k+1,j}, and a production A → BC.

Membership: w ∈ L(G) exactly when S ∈ X_1n — the start symbol can generate the entire string.

Visually, this builds a triangular table: the bottom row holds every X_ii, aligned directly under each input symbol; each row above combines two adjacent smaller entries; the single cell at the very top is X_1n — the answer to the whole question.

CYK · 02

Interactive — Parsing "baaba"

A concrete grammar, a concrete string, and a table you build one diagonal at a time. Click any filled cell once it's revealed to see exactly which split point and which rule put it there.

S → AB | BC    A → BA | a    B → CC | b    C → AB | a
The bottom diagonal (length-1 substrings) is shown to start. Press Reveal next diagonal to build the table upward, or click any highlighted cell to see how it was computed.

Once X₁,₅ — the top cell — is revealed, check whether S is a member. If it is, baaba ∈ L(G); if not, it isn't. Every intermediate cell you clicked along the way is the actual evidence for that final answer, not just a rubber stamp.

CYK · 03 · Beyond the slide

Why O(n³)?

Not on the lecture slides directly, but a natural — and standard — follow-up once you've built the table by hand.

The table has one entry X_ij for every pair i ≤ j — that's n(n+1)/2 cells, so O(n²) entries overall. Filling in a single entry X_ij of length L = j − i + 1 means trying up to L − 1 split points, each an O(1) lookup against a grammar of fixed size. In the worst case that's O(n) split points per cell.

O(n²) cells  ×  O(n) split points per cell  =  O(n³) total

Notice again where CNF is doing the work: because every production is exactly binary, "trying a split point" is the only kind of work a cell ever needs. A grammar with unbounded right-hand sides wouldn't just be slower to parse — it wouldn't fit this table-filling structure at all.

Part V — Consolidate
Consolidate · 01

Trap Museum

Ten ways this conversion goes wrong on an exam, gathered from every stage of the pipeline. Each one already appeared inline above — this is the one place to review all of them at once.

1 — Forgetting "no useless symbols" is part of the definition
  • A grammar where every rule is syntactically shape (1) or (2), but some variable can never contribute to any derivation, is not in CNF. The two-shapes rule and the usefulness rule are both required, not either-or.
2 — Checking reachable before generating
  • Generating-ness has to be computed on the original rule set; reachability has to be checked last, on whatever survives. Reversing the order can leave a genuinely useless symbol behind, looking falsely reachable.
3 — Adding back the fully-empty body during ε-elimination
  • If every symbol in a body is nullable, dropping all of them just re-derives an ε-rule you're trying to eliminate. Always exclude that one combination.
4 — Treating repeated nullable occurrences as a single decision
  • aAA has two independent nullable positions, not one — that's 2² = 4 combinations, not 2. Underexpanding here silently drops legal strings from the language.
5 — Re-adding X → ε for a non-start variable
  • The ε-exception belongs to the start symbol alone, applied once, at the very end — never mid-algorithm for an arbitrary variable you happen to be expanding.
6 — Naive substitution during unit-elimination, instead of computing closure
  • Unit cycles (A → B, B → A) make repeated ad-hoc substitution loop forever. Compute the full reflexive-transitive closure of unit pairs as a finite set first, then copy productions once.
7 — Missing unit-pair chains that lead nowhere
  • If every variable in a unit-cluster only ever chains to more unit rules with no non-unit exit, the whole cluster is dead. This is exactly why useless-symbol elimination runs again after unit-elimination.
8 — Forgetting length-2 bodies that mix a terminal with a variable
  • aB is short enough that BIN wouldn't touch it, but it still violates TERM — shape (1) needs both symbols to be variables. The single most common slip on this whole topic.
9 — Running BIN before TERM
  • Binarizing a body like aBC first just relocates the mixed-terminal problem one level down into a fresh helper variable, forcing a second cleanup pass. TERM first means BIN only ever touches pure-variable bodies.
10 — Reusing an existing variable name for a new helper
  • Every TERM helper and every BIN cascade variable needs a name that doesn't already mean something else in the grammar. A collision silently merges two unrelated meanings into one rule set.

Practice Problems

Four problems, spanning the full pipeline and a CYK drill. Work each one before opening its solution.

Problem A

Convert to CNF

S → aXb | c,   X → aXb | ε

Show full solution

Nullability: X is nullable directly. S is not — both of its bodies always contain a terminal regardless of X.

ε-elimination: S → aXb → aXb | ab (keep S → c as is). X → aXb → aXb | ab; discard X → ε. S not nullable ⇒ no S → ε added.

S → aXb | ab | c    X → aXb | ab

Unit-elimination: no unit rules exist anywhere in this grammar — unchanged.

Useless symbols: both variables generating (X → ab, S → c) and reachable (X via S → aXb) — nothing removed.

TERM: introduce Ta → a, Tb → b (note: even the all-terminal body ab needs both terminals replaced — shape (1) requires every symbol in a length-≥2 body to be a variable).

S → TaXTb | TaTb | c    X → TaXTb | TaTb

BIN: only TaXTb (length 3) needs it, in both rules. One helper: H → XTb.

Final:   S → TaH | TaTb | c
X → TaH | TaTb
Ta → a    Tb → b    H → XTb

Check: L(G) = {aⁿbⁿ : n ≥ 1} ∪ {c}. Test aabb in the CNF grammar: S → TaH → a·(XTb) → a·(TaTb·b) → a·(ab)·b = aabb. ✓

Problem B

Is this grammar in CNF?

S → AB | a,   A → BB | ε,   B → b

Show full solution

No. Check every rule against the two shapes: S → AB ✓ shape (1). S → a ✓ shape (2). A → BB ✓ shape (1). B → b ✓ shape (2). Three out of four rules are fine — the problem is A → ε.

The ε-exception only ever covers the start symbol. A is not the start symbol here — S is — so A → ε is illegal regardless of whether ε ∈ L(G) or not.

(As it happens, does this grammar even generate ε? S's bodies are AB and a — a is nonempty, and AB needs B which is never nullable, so no: ε ∉ L(G) at all. The A → ε rule isn't just misplaced — it's dead weight that should have been eliminated by the standard pipeline before ever reaching a "final" CNF grammar.)

Problem D

Conceptual check

Using the capstone grammar (S → ASA | aB, A → B | S, B → b | ε) — how many variables does the final CNF grammar have, and why?

Show full solution

Five: S, A, B (the three original survivors — nothing was ever removed by useless-symbol elimination) plus U (one TERM helper, for the single terminal a that ever appears mixed into a longer body) plus C₁ (one BIN helper, for the single length-3 body ASA that appears in both S and A's rules — reused rather than duplicated, since it's the exact same three-symbol pattern in both places).

Consolidate · 03

Cheat Sheet

One page, everything above, compressed.

CNF definition

  • A → BC or A → a, nothing else
  • No useless symbols
  • Exception: S → ε only, only if ε∈L(G), only if S never appears on any RHS

The four steps, in order

  • i. Eliminate ε-productions
  • ii. Eliminate unit productions
  • iii. Eliminate useless symbols
  • iv. TERM, then BIN

ε-elimination

  • Nullable: direct ε-rule, or all-nullable body
  • k nullable occurrences → 2ᵏ versions, minus the empty one
  • S → ε added once, only if S nullable

Unit-elimination

  • Unit pair: reachable via unit rules only
  • Compute closure as a set, don't substitute naively
  • Copy non-unit bodies across every pair, then drop unit rules

TERM & BIN

  • TERM: one helper per distinct terminal in a multi-symbol body
  • BIN: cascade helpers for bodies of length ≥ 3
  • Always TERM before BIN

CYK recurrence

  • X_ii = {A : A→aᵢ}
  • A∈X_ij iff ∃k, B∈X_ik, C∈X_(k+1)j, A→BC
  • Membership: S∈X_1n
  • Runs in O(n³)
